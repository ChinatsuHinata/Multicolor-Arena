# 回放训练标注

在主界面「设置」中开启「回放训练模式：标注关键步骤与推荐招法」。回放中的「设置」也可以开关。默认关闭，设置会保存。

进入「对局回放」，暂停在需要评价的局面，点击右下角「标注当前步骤」。标注的是当前画面里的状态，推荐操作从此状态开始；如果要评价刚才的走法，先退回它发生前的步骤。

## 牌手操作

1. 选择评价哪一方。新标注遇到电脑的主阶段时会默认选择电脑方，已有标注仍按原评价方打开。双方分别保存，座位与观看视角不会混淆。
2. 在「关键点评」写问题、理由和预期后果；在「推荐路线」按顺序写出牌、目标、模式、后续效果选择和留费。建议每个标注只讨论一个明确决策。
3. 新录制的完整主阶段决策点可选择「下一步推荐操作」。「较差的对照操作」会默认选择「电脑实际操作（录像）」：从紧接着的录像步骤读取电脑真正执行的出牌、目标、模式、攻击或过牌，即使该操作不在启发式候选列表中也可选择。它保留录像里的原操作，不会用已经更新的 AI 策略重新猜测。如果要比较别的招法，也可手选其他候选或选择「不比较其他操作」；推荐与对照不能是同一个动作。
   推荐候选仍由现有策略提供，不是全部合法目标、模式与支付方式；没有适合的推荐候选时，填写文字推荐也可以保存电脑实际对照，但这种标注尚不形成数值偏好对。
4. 选择判断把握。若判断依赖回放里看到的对手隐藏手牌，勾选「事后分析」；这类点评会保存，训练转换时排除。
5. 点击「保存标注」或「保存并关闭」。关闭和切换评价方会保存编辑内容；保存失败时保留面板与输入。重新打开同一录像会载入原标注。同一步同一方重复保存是修改，不会增加重复样本。
6. 点击「导出训练文件」。所有步骤的标注合并为一个文件，写在游戏 EXE 旁的 `training/` 目录；开发环境写在项目根目录的 `training/`。文件名含录像名与内容哈希，扩展名为 `.training.json`。删除按钮仅删除当前步骤、当前评价方的标注。

录像本体不改动。分享训练文件即可取得可见局面、数值特征、标签、实际终局结果与定位信息；需要完整复盘时再一并分享 `.mreply`。

## 能直接用于哪种训练

JSON 格式为 `multicolor.ai.human_annotations.v1`：自动保存录像 SHA-256、录制规则指纹、导出游戏版本、局次、游戏 ID、步骤（内部从 0 开始）、序列号、回合、评价座位、可见观察和 9 项局面特征。

- **文字标注**：`comment` 与 `recommended_text` 保留牌手原意，供后续教师解释、特征补充和人工审核。当前数值训练器不会把文字自动解释成可执行路线。
- **行为示范**：选择的推荐操作带动作类型、实例 UID、目标与模式，可供后续行为模型消费；目前没有新增全策略行为模型。
- **偏好训练**：明确选择推荐和对照，且两个公开启发式推演端点均完成时，可训练端点评分。自动支付、触发选择和对手响应使用现有启发式，不等同于牌手指定的完整路线，也不是完整对手回合预测。未知抓牌造成不完整端点时，不生成可训练的偏好对。
- **终局价值训练**：原始录像中的真实局面与该局实际结果可接入已有价值训练器。实际胜负始终与假设推荐分开，未完成局不视为平局。

旧录像仍能标注文字、导出实际局面特征和终局结果。旧格式没有记录被清除的私有选择状态，因此不生成「已验证下一步操作」。新录像会额外记录是否为没有待选、堆叠或战斗的主阶段决策点。非主阶段、终局与缺少己方手牌的步骤同样保留文字标注。

电脑实际对照也需要在操作前的完整主阶段决策点提取；选错评价方、录像末尾、缺少紧接着的动作或跨到另一局时不会伪造操作。该操作的训练端点仍从当前局面的己方手牌和公开区域推演，不直接复制录像里将来的手牌或实际胜负。保存文件中的 `comparison_action.source="replay_actual"`、`recorded_frame` 和 `recorded_sequence` 记录来源，重开时恢复实际对照选择。

训练观察隐藏对手未知手牌，不输出双方牌库顺序。当前回放转换不恢复对手曾公开展示的手牌记忆，采取更保守的未知处理。

## 开发侧转换与训练

在仓库根目录执行；`$py` 替换为实际 Python 3 路径。至少标注两份独立录像，才能分离训练与验证。

```powershell
$py = 'C:\Users\Lenovo\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
$labels = Get-ChildItem -LiteralPath training -Filter '*.training.json'
& $py tools/ai/prepare_human_training.py @($labels.FullName) --output work/ai-training/human-outcomes.json --preferences-output work/ai-training/human-preferences.json

# 真实终局价值；训练部分必须同时有胜负标签
& $py tools/ai/train_value.py work/ai-training/human-outcomes.json --output work/ai-training/human-value.json

# 明确的操作偏好；训练与验证录像都必须有可区分的端点对
& $py tools/ai/train_preferences.py work/ai-training/human-preferences.json --output work/ai-training/human-preference-value.json
```

转换器按录像内容哈希分组；同一录像的双方、各局和所有步骤都进入同一分组。按哈希排序保留最后一份录像验证，其余训练。拒绝混用不同录制规则指纹和重复录像标注。偏好训练按录像均衡样本权重，降低长录像占据全部梯度的影响。文字、事后分析和不完整端点不会被伪造成偏好或胜利标签。

两个训练入口均输出运行时可加载的实验价值参数，不能据此认定棋力提升，也不会自动修改默认 AI。仍需独立 arena、关键局面回归与延时验证。若两条路线的 9 项特征完全相同，当前偏好模型无法区分，需要扩充特征。

随机效果端点使用由公开序列号派生的固定假设情景，导出 `rng_policy` 与 `rng_seed`；它不是录像私有随机状态，也不是未来结果或随机分支平均值。两条比较路线必须采用相同随机情景，转换器会校验并保留该来源。
