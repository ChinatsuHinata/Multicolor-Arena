# 云端版本更新（客户端已停用）

当前 Windows 和安卓客户端已移除标题界面的手动入口、启动时自动检查、更新提示和下载逻辑。以下保留原 1.2.7 云端更新方案记录；发布脚本和 ECS 文件服务仍在，但当前客户端不会读取 `updates/latest.json`。用户需通过外部渠道获取补丁或完整安装包。

## 原客户端方案（已停用）

- Windows：点击「更新」后在游戏用户数据目录的 `updates` 文件夹下载完整安装器；大小及 SHA-256 与签名清单一致后才允许启动。确认后游戏退出，Inno Setup 沿用原安装目录，并保留独立牌组、回放和设置。
- 安卓：点击「更新」会打开 ECS 的 APK 下载链接。下载和覆盖安装由浏览器及安卓系统确认，游戏不会尝试静默安装。必须保留相同包名和签名证书，否则安卓会拒绝覆盖旧版。
- 1.2.6 及更早客户端没有更新入口，需要先手动安装一次 1.2.7 或更新版本。之后的新版本才能收到应用内提醒。

## ECS 入口

`relay/update_gateway.py` 在原 TCP 47862 端口提供 `/updates/` 文件，并把原 WebSocket 请求转给仅监听 `127.0.0.1:47866` 的 Godot 中转服务。原 UDP 47862、账号服务和玩家使用的 WebSocket 地址保持原样，无需增加安全组入口。网关支持下载断点续传的 HTTP Range。`relay/deploy.ps1` 上传网关及服务配置，`install-user.sh` 切换服务并进行本机连通性检查，切换失败时恢复原 WebSocket 服务。切换会中断正在进行的云端房间，部署前需选择无对局时段。

当前 ECS 只开放原有公网端口且没有 HTTPS 域名。清单以本地私钥签名，客户端内置公钥核验；私钥存放于忽略提交的 `.godot-toolchain/release-signing.key`，不会上传到 ECS。文件传输仍是 HTTP，Windows 客户端从签名清单核验完整安装包；安卓覆盖安装由系统核对原 APK 证书。首次安卓安装及浏览器下载页没有 TLS 保护，正式大规模发行建议配置可自动续期的 HTTPS 入口。阿里云 ECS 流出流量会产生费用。

## 发布下一版

1. 修改 `project.godot` 的 `config/version`，使用三个或四个数字段，且高于已发布版本。
2. 保留原安卓调试签名密钥及本地发行清单私钥。发布脚本检查包名 `com.example.multicolorarena` 和现有签名证书指纹，防止产出无法覆盖安装的 APK。
3. 首次部署在项目根目录运行 `powershell -ExecutionPolicy Bypass -File .\relay\deploy.ps1`，随后运行 `powershell -ExecutionPolicy Bypass -File .\tools\publish-ecs-update.ps1`。两项通过已有 ECS SSH 私钥连接，私钥口令需在本机交互式终端输入。
4. 发布脚本导出 Windows、安卓，做跨平台资源核对，编译 Windows 完整安装包，计算 SHA-256，生成签名清单，上传到 ECS 暂存目录，在服务器再次核对三个文件后原子切换 `latest.json`。需要先检查本地文件时加 `-PrepareOnly`；文件已经导出时加 `-SkipBuild`。

`builds/releases/<版本>/update.json` 是签名清单，包含各平台版本、ECS 地址、文件大小和 SHA-256。Windows 包约 730 MiB，安卓包约 760 MiB；ECS 要预留至少两个包加暂存空间。安卓目前沿用项目的调试签名发布方式，日后改用正式签名会影响覆盖安装，须规划一次迁移。
