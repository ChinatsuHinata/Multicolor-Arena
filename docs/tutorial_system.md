# 配置驱动教程系统

## 教程文件目录与现有课程

教程目录为 `data/tutorial/catalog.json`，课程 JSON 按教程列表的三个分类分别放在 `data/tutorial/beginner/`、`data/tutorial/advanced/`、`data/tutorial/leader/`。目录中的路径须指向实际课程文件；课程 `category` 与所在文件夹对应。当前已制作的课程都属于新手教程，进阶和自机文件夹为后续课程预留。Windows 两个导出预设均包含目录及分类子文件夹中的 JSON。

`data/tutorial/beginner/t1.json` 实现 `tutorial/t1.txt`：以 50 张蕾米莉亚主卡组为展示场景，按 d1–d10 依次讲解自机、同名限制、副卡组及颜色。红框标出自机、四张「宵暗ノ翼」和两张限制级「不夜城」；d9/d10 在指引中显示蕾米莉亚卡图。q1 显示夜王卡图，答案为颜色值 5；答错可重选，答对进入 d11 并完成课程。课程 ID 为 `t1`，完成记录按该 ID 保存。专项检查为 `tests/test_tutorial_t1.gd`。

`data/tutorial/beginner/t2.json` 实现 `tutorial/t2.txt` 的开局练习：用四个确定性战场局面展示起手、首回合、第二个自己的回合和蕾米莉亚登场。起手任务要求玩家在真实手牌中选中「夜王」和「天火人」并确认调度；选错不改变局面，选对后由原规则补抓两张牌并进入准备阶段。莉莉黑入场时任务要求选红色，其他颜色在提交前被拒绝，保留原颜色选择。其余操作使用真实凭依、使用牌和攻击，任务以卡牌区域、莉莉黑的红色指示物和生命值检查推进；两次红色凭依任务在完成错误交换后立即失败并恢复任务起点。当前任务条件不能检查具体支付来源或逐个攻击动作，后续回合由场景跳转构造确定性局面。专项检查为 `tests/test_tutorial_opening.gd`、`tests/test_tutorial_mulligan_selection.gd`、`tests/test_tutorial_lily_opponent.gd` 和 `tests/test_tutorial_lily_ui.gd`。

`data/tutorial/beginner/t3.json` 实现 `tutorial/t3.txt` 的单位牌课程：空场开篇、牌面属性与名称限制、双方战斗、歼灭／英勇／疾行／结晶／先制／威吓／退治固定演示、双重阻挡伤害分配任务、自机颜色约束任务，以及最后的残局。双重阻挡要求玩家亲自分配伤害，云山存活或拉尔瓦死亡时重置；结晶演示预置已横置的颜色盘费用，由云山阻挡并消灭吸血鬼妖精后在固定动作序列中指定结晶目标；先制词条由三费云山阻挡三费蕾米莉亚演示。倒数第二题以「蕾米莉亚的烛台」作为初始永久物；末题双方套牌自机已在战场，对方有三只明确的 4/4/2 青蛙衍生物。残局只规定初始局面和击败对方的目标，不预置答案。专项检查入口为 `tests/test_tutorial_t3.gd`，结晶演示的独立检查为 `tests/test_tutorial_t3_crystal.gd`。

`data/tutorial/beginner/t4.json` 实现 `tutorial/t4.txt` 的非符课程：原稿讲解保持原话，辨认非符后，依次演示单体去除、扫场、召唤、资源、颜色盘跳费与多功能非符。召唤段补充宵暗之翼与三费蕾米莉亚、秘神的门扉翻出七费天子、幽冥境制造七点小鬼后，在结束阶段的牺牲能力进入堆叠时响应辉夜，移除牺牲能力并保留小鬼。羽衣展示四费套牌自机灵梦离场后选择回手；昼酒处理六费套牌自机蕾米莉亚；出鞘的我方战场为空、幽幽子尚未出场。血族末裔保留八云蓝，由蓬莱之药复活套牌自机永琳并拿回青花。每个演示使用真实卡牌结算，专项检查入口为 `tests/test_tutorial_t4.gd`。

## 当前课程与通用能力

当前目录注册 `data/tutorial/beginner/t1.json`、`data/tutorial/beginner/t2.json`、`data/tutorial/beginner/t3.json` 与 `data/tutorial/beginner/t4.json`。教程列表仍支持新手、进阶和自机三个分类；没有课程的分类显示空状态。完成状态按课程 ID 保存。

教程引擎仍支持战场、卡组与组卡器场景，任务、指引、对手调度和检查点由课程配置控制。新增课程时应先创建实际课程 JSON，再将路径加入目录。

## 总体目标与边界

教程分为教学场景、指引、任务和对手控制器四部分。以后增加受支持的课程时，填写课程 JSON 并加入目录即可。教程复用真实卡牌、战场、操作、支付和结算，不复制规则，也不在核心规则函数里加入步骤数字判断。

本轮采用独立本地引擎实例，不建立联机会话，不修改协议。教学局面不读取或写入玩家卡组文件，不使用普通对局存档，不生成普通回放或触发回放保存提示。既有设置文件只增加按稳定课程 ID 保存的完成标记，使用项目已有 `complete_tutorial()`。课程中的对手策略不会修改普通 AI、自机 AI 档案或实验 AI 设置。

「场景」是可加载的局面数据，不需要每课一个 `.tscn`。课程开始加载 `initial_scenario`；只有步骤显式填写 `scenario` 才切换局面。场景构造属于受控初始化，预置永久物不会重放进场异能，预置手牌不会重放抓牌异能。开始实际操作后，规则继续由原引擎执行。

## 已确认的原有接口

以下均由本仓库代码确认，不是拟议接口。

| 范围 | 原有实现 | 教程接入方式 |
| --- | --- | --- |
| Godot | `project.godot` 的 4.7 特性；本地工具链 `Godot_v4.7.2-stable_win64_console.exe`，GDScript | 使用现有运行环境，无新增依赖 |
| 卡库 | `scripts/card_database.gd::load_cards()`；`deck_store.gd::CARDS` | 校验注册卡库里的定义 ID，不能只判断 JSON 文件存在 |
| 普通初始化 | `duel_engine.gd::start(a,b,first,seed)` | 原方法会洗牌、抓四张、进入调度；教程构造独立局面，不调用这个普通开局流程 |
| 卡牌实例 | `make_card()`、`find_card(uid)`、`ref_target(card)` | 实例包含 `uid`、`epoch`、`card_id`；别名绑定本局 `uid`，高亮读取当前 `epoch` |
| 游戏状态 | `players`、`stack`、`pending`、`entry_choices`、`combat`、`active`、`priority`、`phase`、`turn`、`revision`、`rng` | 教程仅在初始化或明确恢复时设置局面；运行时观察状态 |
| 真实玩家操作 | `commit_cast()`、`commit_ability()`、`commit_extension()`、`attack()`、`pass_priority()` 及选择方法 | 原对战 UI 继续直接调用这些方法；教程程序化提交通过现有 Gateway |
| 操作检查 | `net/command_gateway.gd::apply(engine,seat,command)` | 适配器复用白名单和参数/支付检查；不发送网络包 |
| 回合、执行权 | `start_turn()`、`pass_priority()`、`advance_phase()`、`finish_turn()` | 保留真实执行权、堆叠及结算顺序 |
| 规则观察 | `revision`、`history`、`presentation_events`；表现事件会被 UI 消费 | 本轮以版本号和状态边界观察，不把表现事件当作完整规则事件总线 |
| AI | `duel_view.gd::_process()` 调用 `LocalExperiment.step()`，后者可调用真实 `ai_step()` | 教程入口禁用普通调度，由独立有限规则控制器负责 |

| PC/Android | `ui_layout.gd`、`battle_ui_layout.gd`、安全区域与字体/触控度量 | 指引用相同颜色、按钮、面板样式及逻辑像素度量 |
| 状态保存 | `net/state_codec.gd::capture()` / `restore()` | 内存检查点复用图编码，保留共享引用、随机种子/状态及规则队列 |
| 回放 | `duel_view.gd::render()` 中的 `ReplayArchive.record()` / `finish()` | 教程分支不调用普通回放录制 |
| 教程入口 | `tutorial_list.gd`、`main.gd::tutorials()`、`complete_tutorial()` | 注册 JSON 课程；复用列表、分页与完成保存 |
| 测试 | `tests/AGENTS.md`；SceneTree 专项测试，UI 辅助在 `tests/support/ui_base.gd` | 新增两个专项测试，保留既有回归入口 |

## 配置结构（schema_version = 1）

文件使用 UTF-8 JSON。目录 `data/tutorial/catalog.json` 的 `lessons` 是课程文件路径数组，课程配置位于 `data/tutorial/` 的分类子文件夹下。旧配置不写 `Scenario.type` 时仍按原战场弹框方式启动。

### 三类场景

| 类型 | 呈现与数据 | 当前课程 |
| --- | --- | --- |
| `battlefield` | 真实战场铺满画面，教程弹窗在战场内部；单卡放大与说明按类别左右或上下排列；`focus.alias` 定位本局实例 | `t2` |
| `deck` | 左侧教学标签、右侧复用套牌广场的卡组总览；PC 点击或右键卡图在左侧显示详情，Android 长按 1 秒显示广场式详情弹窗；教学卡组只读 | `t1` |
| `in_game` | `screen: "deck_editor"`；真实组卡器铺满场景，紧凑指引嵌入编辑器内部，使用独立临时 draft | 暂无 |

战场复用铺满窗口的 DuelView，教程弹窗就在战场内部；卡组和组卡器保留 PC/Android 原生界面，直接在窗口中渲染，避免子视口先绘制再缩放导致 PC 卡图失真。卡图继承线性 mipmap 过滤。卡组教学继续采用左侧标签、右侧卡组的形式，右侧卡图按原生尺寸绘制。组卡器等游戏内场景的指引直接挂在原生宿主内部，不再占用界面外的独立左栏。PC 指引优先放在主卡组区域下方，任务步骤可操作顶部排序按钮；Android 指引放在安全区域内部下方，可隐藏以查看全部卡牌。运行状态在独立 Runtime 节点中。恢复按钮扫描可见按钮以避让，窗口缩放后重新检查位置与安全区域。

卡组教学的 PC/Android 总览均复用 `deck_plaza_overview.gd`，右侧面板铺满可用高度；PC 主卡组区域随面板高度扩展，副卡组放在底部。PC 点击自机、主卡组或副卡组卡图后，左侧说明区显示详情，教程的下一步和退出按钮仍保留；点击关闭恢复同一步的教学文字。Android 沿用套牌广场的三栏总览、分页及长按 1 秒查看方式，详情弹窗放在教学场景的安全区域内。查看和关闭详情不编辑卡组、不推进步骤；弹窗挡住下方卡牌输入。卡图、费用和规则文本与套牌广场共用 `card_inspection.gd`，包含横向卡图方向和异画选择。

组卡器内嵌指引的 PC 标题/正文为 22/18，按钮高度 40；模拟 Android 为 30/26，按钮高度 64。面板高度分别为 296/360，长说明在面板内部滚动。卡组教学左侧标签使用原有字体度量和全高侧栏。Android 原生界面重建后，指引保持在 GUI 输入顺序最后；指引按钮不进入组卡任务动作门控，触摸指引不会触发下方卡牌。

`deck` / `in_game` 场景不创建对局引擎、不安排 AI、不生成回放，不能配置战场专用状态或对手。其 `deck` 包含 `name`、真实定义 ID `leader`、`main`、`side` 和 `rule_set`，规则集默认 `official`。加载时复用 `DeckStore.validate` 的非严格卡组检查，允许不足 50 张的教学卡组，但仍检查卡库、可构筑性、同名限制、主副卡组容量等。

```json
{
  "type": "in_game", "screen": "deck_editor",
  "deck": {"name": "练习卡组", "leader": "70", "main": ["164", "2", "1"], "side": [], "rule_set": "official"},
  "components": {"editor_surface": {"visible": true}, "interaction": {"enabled": true}}
}
```

游戏内界面第一版只注册 `deck_editor`。正式卡组、普通编辑 draft、正常 AI 设置和文件存储不与这个临时宿主共享；保存、导入导出、上传、选择正式卡组与导航等入口均不在教程允许动作集合内。

### Tutorial

```json
{
  "schema_version": 1,
  "id": "example_course",
  "title": "示例课程",
  "initial_scenario": "board_basics",
  "start_step": "welcome",
  "completion": {"type": "steps_completed", "steps": ["welcome", "resources"]},
  "scenarios": {"board_basics": {}},
  "steps": {"welcome": {}, "resources": {}}
}
```

上面的空对象仅表示结构；当前完整可运行配置见 `data/tutorial/beginner/t1.json` 和 `data/tutorial/beginner/t2.json`。场景和步骤均以稳定字符串 ID 为字典键；`$complete` 是结束跳转目标。完成条件在到达终点时检查，不成立会报告具体课程错误。

### Scenario

| 字段 | 本轮行为 |
| --- | --- |
| `seed` | 必填正整数；固定局面及后续规则随机数，不用全局随机源 |
| `first`、`active`、`priority` | 0/1；先手、当前回合方、执行权 |
| `turn` | 普通场景为正整数，默认 1；起手调度场景使用 0 |
| `phase` | 支持 `prepare`、`main`、`end` 稳定边界，以及起手调度专用的 `mulligan`；默认 `main` |
| `players` | 必须恰好两项 |
| 玩家 `name`、`life` | 显示名；正整数生命，默认 20 |
| 玩家 `leader` | 真实自机牌定义；生成本局独立自机实例 |
| 玩家 `leader_zone` | 套牌自机所在区域：`leader`、`deck`、`hand`、`field`、`palette`、`grave`、`exile`；保存初始场面时写入实际区域，加载时将同一个自机实例放回该区域并保留别名及状态 |
| 玩家 `leader_on_field` | 兼容已有课程的可选布尔值；未配置 `leader_zone` 时，true 对应战场，false 或省略对应自机区 |
| 玩家 `extra_leaders` | 可选额外自机实例数组，每项包含卡牌配置和 `zone`（默认 `leader`）；布置时复制自机区卡牌会写入此数组。未配置时保留卡牌规则生成的额外自机；显式空数组表示不预置额外自机 |
| 玩家 `deck_order` | 牌库顶到底的剩余牌序，不能为空；逐项 `card_id`，不会额外洗牌或抓牌 |
| 玩家 `hand`、`field`、`palette`、`grave`、`exile` | 独立实例数组；颜色盘最多八张，包含放在颜色盘的套牌自机和额外自机 |
| 卡牌 `alias` | 可选场景内唯一字符串，绑定生成的实例 `uid` |
| 卡牌 `position` | 仅战场支持，唯一且在本方战场数组范围内；按此排序后交给原有单位/道具/支援排列，不接受任意 3D 坐标 |
| 卡牌 `state` | 布尔 `tapped`、`attacked`；非负整数 `damage`、`timer`、`entered`、`entered_turns`、`plus_counters`、`minus_counters`、`poverty`、`leader_counters`、`courage`；颜色数组 `color_counters`、`token_colors` |
| 预置青蛙衍生物 | 仅战场卡牌项可写 `card_id: "roster_token_frog"`、`token_name: "青蛙衍生物"`、`token_value` 和 `token_spirit`；用真实衍生物定义构造指定攻击／血量与灵力，不接受任意自造卡牌定义 |
| 玩家 `state` | 布尔 `potato`、`mulligan_done`；非负整数 `turns`、`possession_count` |
| `components` | 下述组件显示和交互策略 |
| `opponent` | 初始对手策略和有限响应规则 |

资源使用原规则中的颜色盘、牌色、横置状态及 `potato`。不引入教程独有的支付点数。初始化调用真实 `make_card()` 和卡牌特有开局初始化；额外自机默认由现有规则产生，也可由布置结果明确配置。校验战场容量、称号冲突、致死伤害和入场回合时复用真实规则与属性。

定义 ID、实例 ID 和别名职责不同。例如 `card_id: "70"` 在自机区和颜色盘中各有一张；两张拥有不同的 `uid`。`student_leader` 和 `red_yellow_resource` 明确指向不同实例。区域变更后别名仍指向这个 `uid`，而规则目标使用当前 `epoch` 避免旧目标误认。新场景会生成自己的别名绑定。

战场组件为 `battlefield`、`hand`、`opponent_hand`、`inspection`、`hud`、`stack`；卡组场景注册 `deck_surface`，游戏内场景注册 `editor_surface`。各场景还支持 `interaction.enabled`。呈现组件支持 `visible` / `highlight`；当前场景没有的组件会报出具体字段。隐藏指引不改变组件策略；恢复和退出教程按钮保持可用。当前不支持任意节点路径或对单个普通按钮做视觉禁用。

卡组场景的只读查看不受 `interaction.enabled` 关闭操作权限的影响：自机、主卡组和副卡组都支持 PC 右键（也保留左键）查看、Android 原生触摸长按 1 秒查看。查看或关闭详情不会修改卡组、推进步骤或触发任务失败；答题框显示时仍拦截背景卡组输入。

### Step 与 Guide

```json
{
  "type": "info",
  "guide": {
    "text": "讲解文字",
    "targets": [{"alias": "luna_on_board"}, {"player": 0}],
    "popup": "show",
    "next_button": "manual"
  },
  "next": "resources"
}
```

`type` 支持 `info`、`task`、`wait`。`next` 必填，`failure` 为可选失败目标；`restore_on_failure` 明确指定失败时恢复该步骤入口的内存检查点，默认不恢复。可选 `scenario` 明确切换局面；即使填写当前场景 ID 也视为重新加载。

战场步骤可配置 `camera_view` 与 `open_zone`，讲解、任务和等待步骤均支持。两项仅适用于 `battlefield` 场景，卡组和组卡器场景使用时会报出具体字段错误。

| 步骤字段 | 配置与行为 |
| --- | --- |
| `camera_view` | `"battlefield"` 战场、`"own_palette"` 我方颜色盘、`"enemy_palette"` 敌方颜色盘。PC/Android 均移动真实战场摄像机，保留当前 2D/3D 投影。省略时沿用当前场景最后配置的视角；尚未指定时沿用原有视角行为。配置视角后，普通凭依/支付自动聚焦不会覆盖教程指定的视角。 |
| `open_zone` | `{"player":0,"zone":"grave"}` 打开我方墓地；`player:1` 为敌方，`zone:"exile"` 为移除区。每步打开一个区域列表，使用真实区域卡牌与原有查看组件；指引和列表左右排列。下一步未配置时关闭列表，完成或报错时关闭。 |
| `guide.targets` 中的 `alias` | 标记战场、颜色盘或自机区的指定实例，复用战场卡牌 Outline/Halo，以与卡组教学相同的 `#ff4545` 红色边框显示。叠放卡牌中被标记的实例单独显示。组件和玩家目标仍使用原有指引框。 |

视角、区域列表和红框随步骤推进、上一步、任务重置及检查点恢复更新。隐藏指引保留当前视角与红框；被标记卡牌离开场上后清除场上红框。红框只改变呈现，不改变操作选择、支付或规则目标。打开区域列表也不会提交游戏操作；指引关闭操作权限时仍可查看列表。

```json
{
  "type": "info",
  "camera_view": "enemy_palette",
  "open_zone": {"player": 1, "zone": "exile"},
  "guide": {
    "text": "查看敌方颜色盘及移除区。",
    "targets": [{"alias": "enemy_resource"}],
    "next_button": "manual"
  },
  "next": "next_step"
}
```

`enemy_resource` 必须在该步骤当前场景的卡牌配置中定义为 `alias`。同一 `card_id` 的多个副本可分别命名，以精确标红其中一张。专项验证入口为 `tests/test_tutorial_battle_presentation.gd`。

Guide 的 `text` 是非空纯文本；`targets` 的每项恰好包含 `alias`、`player`、`component` 或 `card_id` 中的一项。`popup` 为 `show` / `hidden`；`next_button` 为 `manual` / `auto` / `hidden`。讲解支持手动或自动推进；任务和等待步骤必须隐藏下一步按钮，通过判定推进。用户隐藏弹框不影响当前步骤、别名、检查点和判定。

可选 `guide.image` 支持有序多图，最多 12 张，适用于所有场景及节点类型。`layout` 为 `row`（横向并排）、`column`（纵向排列）或 `grid`（网格）；网格 `columns` 为 1 至 4，默认 2。`items` 的每项为 `{"card_id":"70","art_id":"tts_151600"}`（明确指定卡牌和卡图版本，省略 `art_id` 使用默认卡面），或 `{"png_base64":"<PNG 图片的 Base64 编码>","name":"示意图.png"}`（自定义图片，名称可选）。横卡、竖卡按原方向等比显示，可与自定义图片混排。卡图引用现有卡库，支持默认卡面和异画，允许展示不在教学卡组中的卡牌；配图只影响展示。

```json
"image": {
  "layout": "grid",
  "columns": 2,
  "items": [
    {"card_id": "70", "art_id": "tts_151600"},
    {"card_id": "100"}
  ]
}
```

旧版单图 `guide.image: {"png_base64":"..."}` 仍可无损打开；仅在修改配图后写为多图配置。自定义图片内嵌到课程 JSON，不保存外部路径，移动课程或删除原图后仍可打开。导入支持 PNG、JPG/JPEG 和 WebP，原文件不超过 32 MB；长边超过 2048 像素时按比例缩小，保存为不超过 16 MB 的 PNG，保留透明背景。课程加载校验卡牌编号、卡图版本、排列参数及图片编码、格式和尺寸。PC/Android 指引在文字下方显示配图，长内容可滚动，点击任意一张放大查看该图；点击配图及关闭放大视图不提交游戏操作或推进教程，隐藏指引保留配图，切换节点时关闭放大视图。

普通对话使用 `type: "info"`，没有必须执行的操作或任务，也不能配置 `task`。手动讲解直接点击「下一步」即可；对话期间无论指引显示或隐藏，战场与组卡器的对局操作都不能执行，对手排队响应也暂停。仍可查看卡牌详情，查看不会推进步骤或触发任务失败。动作匹配、成功／失败判定只用于明确配置的任务或等待步骤。

卡组场景支持用 `guide.targets` 标红特定卡牌，例如 `{"card_id":"164","zone":"main","index":2}` 标红主卡组第三张妖魔书。`zone` 可选 `leader`、`main`、`side`；省略时标红所有区域中的同名卡。`index` 从 0 开始，指定时须同时填写区域；省略时标红该区域所有同名副本。配置校验会检查卡库、当前场景类型以及指定卡牌或副本是否存在。红框由卡组总览绘制，随滚动裁剪、翻页和窗口缩放保留；换步骤、返回上一步或恢复检查点时更新，完成教程时清除。现存课程中的高亮配置见 `data/tutorial/beginner/t1.json`。

卡组场景的讲解和答题也可用 `guide.focus: {"card_id":"74"}` 在指引中展示该卡图；卡牌必须属于当前教学卡组。答题展示卡图时，选项仍独立排列在下方。

Android 题干和教程描述中的大卡图支持原生触摸长按 1 秒查看卡牌详情，长按时在触点显示圆环。详情沿用答题卡牌的独立弹窗，关闭后恢复同一步的文字和已选答案；查看详情不推进教程、不提交答案。轻触不打开详情，移动手指、取消触摸、切换步骤、隐藏指引或应用暂停都会取消长按。

带卡图的教程弹窗按真实卡牌类别排版：单位、道具和自机为左侧文字、右侧大卡图；符卡和结界为上方大卡图、下方可滚动文字。安卓卡组详情与答题卡牌详情弹窗使用相同的类别排版。

配置支持 `layout: "side" / "modal"`；战场默认使用内部 modal 弹窗，卡组教学的 `side` 指左侧标签，游戏内场景的 `side` 指紧凑内嵌指引，沿用现有配置值以兼容课程。战场可配置 `Scenario.focus: {"alias": "…"}`，单步 `Guide.focus` 覆盖它，使用真实卡图放大本局指定实例。任务步骤在非 modal 指引显示时允许操作；modal 显示时屏蔽游戏操作，隐藏后恢复。普通对话始终只读。

### 对话中的固定动作演示

战场的 `type: "info"` 步骤可选配 `sequence`。进入步骤时自动播放，按数组顺序每次提交一个真实动作；上一动作的移动、展示、战斗和结果动画全部结束后，再停顿 0.2 秒才执行下一个。播放期间对话框和「显示指引」按钮隐藏，战斗操作、下一步和上一步暂停；播放完自动显示该步文字及「重置演示」。重置恢复步骤入口的卡牌、费用、触发、对手响应次数和 RNG 状态，并重新播放。普通对话继续直接显示，任务继续使用「重置局面」。演示步骤必须使用可见对话框和手动下一步。

```json
{
  "type": "info",
  "guide": {"text": "观察这次启动能力的 d6 结果。", "popup": "show", "next_button": "manual"},
  "sequence": {
    "actions": [
      {"type": "ability", "player": 0, "source": {"alias": "ice_hero"}, "key": "courage_die", "target": {"alias": "enemy_unit"}},
      {"type": "pass_priority", "player": 1},
      {"type": "pass_priority", "player": 0}
    ],
    "random_results": [{"type": "d6", "value": 6}]
  },
  "next": "after_demo"
}
```

示例要求当前场景中的 `ice_hero` 已有自机能力和至少 2 个勇气等级指示物；可在场景卡牌 `state` 中配置 `courage` 与 `leader_counters`。所有动作仍受真实时机、目标和支付检查约束，非法动作会报告 `steps.<步骤>.sequence.actions.<序号>` 并停止演示。普通对手响应规则在固定演示执行期间暂停。

| 动作 `type` | 参数与含义 |
| --- | --- |
| `pass_priority` | `player: 0/1`，指定一方让过执行权；结算符卡、能力和战斗窗口通常需要双方依次让过 |
| `possession` | `player`、`palette: {"alias":"资源"}`、`hand: {"alias":"手牌"}`；同时省略两个选牌字段表示结束当前凭依选择 |
| `cast` | `player`、`card: {"alias":"牌"}` 或 `card: {"card_id":"定义 ID"}`、可选 `target`；可使用手牌或自机区的指定牌，按真实费用支付 |
| `ability` | `player`、`source: {"alias":"来源"}`、`index` 或 `key` 二选一、可选 `target`；启动能力用真实目标和费用，触发能力由引擎自动产生 |
| `attack` | `player`、`card: {"alias":"攻击者"}`、可选 `target: {"alias":"直接攻击目标"}`；支付真实攻击费用 |
| `block` | `player`、`cards: [{"alias":"阻挡者"}]`；空数组表示不阻挡，仅可在真实阻挡选择时提交 |
| `choose_trigger` / `choose_effect` | `player`、可选 `target`；处理触发及入场能力等产生的实际选择，省略目标表示不发动或跳过可选效果 |
| `choose_trigger_order` / `choose_ward` | `player`、`index`，从 0 开始的触发／护盾顺序选择 |
| `choose_return` / `choose_grave_replacement` | `player`、`yes: true/false`，自机返回或墓地替代选择 |
| `choose_timer` | `player`、`value: -1/0/1`，计时指示物替代选择 |
| `combat_damage` | `player`、`assignments: [{"card":{"alias":"阻挡者"},"amount":2}]`，处理多阻挡者的实际伤害分配 |
| `discard` / `mulligan` | `player`、`cards: [{"alias":"牌"}]`，弃牌或起手调度 |
| `delay` | `seconds`，动画结束后额外等待大于 0、不超过 60 秒；无需 `player` |

`target` 沿用对手出牌的别名、玩家、堆叠来源、`mode`、`color`、`x`、`parts` 和 `picks` 选择格式。需要颜色选择时，可用 `{"type":"choose_effect","player":0,"target":{"color":"红"}}`。被指定的实例不能替换为另一张同名牌；只按 `card_id` 使用牌时，按当前手牌顺序选择该定义的第一张。

投币及 d6 必须事先在 `random_results` 中按**实际发生顺序**逐项填写。`coin` 的 `value: 1` 为正面、`0` 为反面；`d6` 为整数 1–6。例如 `[{"type":"coin","value":0},{"type":"d6","value":4}]` 表示先投反面，再掷出 4。结果在真实规则取随机数时使用，保留原有结果动画和效果；预设缺失、类型顺序不符或播放结束后仍有多余结果，均报出具体字段错误，不会退回随机投掷。洗牌等其他随机行为沿用场景种子；重播恢复相同 RNG 状态。执行中捕获的检查点保存动作和随机结果的消费位置，恢复后从该位置续播；「重置演示」仍从最初入口播放。

专项测试为 `tests/test_tutorial_sequence.gd` 与 `tests/test_tutorial_sequence_ui.gd`，覆盖双方凭依、出牌、能力、攻击／阻挡、投币和 d6、途中恢复、重复播放，以及 PC/Android 的对话隐藏、动画等待和重置按钮。

### Task 与事件等待的最小能力

```json
{
  "type": "task",
  "guide": {"text": "使用妖魔书并等待结算", "popup": "hidden", "next_button": "hidden"},
  "task": {
    "timing": "state_changed",
    "success": {"type": "entity_zone", "alias": "book_in_hand", "zone": "field"}
  },
  "next": "resources"
}
```

此条件在真实出牌结算后满足，卡牌刚进入堆叠不会成功。测试已实际支付费用、双方交还执行权，再观察入场。`timing` 支持 `state_changed`（默认）及 `enter`；进入判定不匹配成功或失败时直接给出错误，避免等不到任何后续判定。可选 `task.failure` 是条件，存在时必须给步骤填写 `failure`；成功和失败同时满足时失败优先。任务的 `task.allow_turn_end` 缺省为 `false`：教程规则引擎会阻止主要阶段结束，界面也会禁用结束按钮。只有显式设置为 `true` 的任务允许按正常规则结束回合。

`task.timing: "mulligan_selection"` 只用于 `mulligan` 战场步骤，`required_aliases` 须指向我方起手牌中的两张实例。玩家在原有手牌区点选两张并点击调度；选错留在本步，选对通过真实调度操作推进。`wait` 步骤须填写 `wait_event`，并使用 `task.timing: "event"`。适配器事件为：

- `state_changed`：真实引擎 `revision` 改变；可能合并一帧内的多次变化。
- `phase_changed`、`priority_changed`：两次观察间的阶段/执行权变化，携带前后值。
- `command_accepted`：仅通过教程适配器 Gateway 成功提交的操作，携带行动方和命令。
- `step_entered`：教程流程进入步骤，携带步骤 ID。

战场状态任务可配置 `required_choice: {"effect":"lily_color","color":"红"}`。该约束在莉莉黑入场颜色选择提交前检查；选错时显示任务提示，局面与待选项保持原状，选对才调用真实规则引擎。颜色选项支持红、蓝、绿、黄、黑。对手的 `pass_priority` 响应遇到玩家待完成的选择时会排队等待，选择完成后继续执行。

普通战场 UI 操作仍直接调用原引擎，因此能产生状态观察事件，**不会**产生适配器的 `command_accepted`；教程颜色选择和起手调度通过适配器提交。状态变化不等同于「玩家准确提交了某动作」，不解析中文日志推断动作，不声明已有覆盖全部规则事件的总线。同一操作产生的一批事件带有步骤世代，不能连续完成新旧两个步骤。

战场条件白名单为 `always`、`all`、`any`、`not`、`steps_completed`、`phase`、`priority`、`pending`、`combat_attacker`、`combat_attacker_rank`、`combat_step`、`entity_zone`、`entity_state`、`entity_color_counter`、`entity_count`、`zone_count`、`player_count`、`life`。`all` / `any` 使用非空 `conditions` 数组；`pending` 使用 `kind` 和 `owner` 检查当前待完成选择；`combat_attacker` 检查当前战斗的攻击者，并核对当前实例 epoch；`combat_attacker_rank` 按当前攻击者在己方场上单位中的数值排名判定，范围可取固定前 N 名或任一方当前单位数；`entity_state` 使用 `key: "attacked"/"tapped"` 和布尔 `value` 检查动作后的卡牌状态；`entity_color_counter` 使用 `color` 检查颜色指示物；`entity_count` 检查伤害及白名单计数；`life` 使用 `player`、整数 `value` 和 `op: eq/le/ge`。对局条件只适用于战场，其他界面使用时会明确报错。未列出的动作判定、攻击结果、特定支付来源等会被明确拒绝，留给后续扩展。

上述五种指定卡牌实例的条件（`combat_attacker`、`entity_zone`、`entity_state`、`entity_color_counter`、`entity_count`）可二选一使用 `alias` 或 `created`。`alias` 指向初始场景中配置的实例；非负整数 `created` 指向该场景加载完成后新创建的实例，包含衍生物、复制品及其他中途生成的卡牌。编号从 0 开始，与录制动作里的 `{"created":N}` 使用相同定位方式，相对于场景起点而非当前任务或当前录制片段起点。编号跟随引擎创建顺序，可能包含中间实例而不连续显示；同名同定义的多个衍生物仍有各自编号。检查点、撤回和任务重置保留这一定位起点；重置后按相同过程重新生成，可以再次匹配原条件。

例如，`{"type":"entity_zone","created":0,"zone":"field"}` 检查生成实例 #0 在战场；`{"type":"entity_state","created":0,"key":"tapped","value":true}` 检查它横置；`{"type":"entity_count","created":1,"key":"plus_counters","op":"ge","value":2}` 检查生成实例 #1 至少有两个＋指示物。实例尚未生成或已消失时，这些单项条件不成立，包括 `entity_state` 的 `value:false`。按原规则衍生物离场后消失，不能用「位于墓地」检查已消失的衍生物；`not` 仍按正常逻辑取反，所以「不在战场」在生成前也可能成立。需要完成生成后再判断离场的任务，应另设先生成的任务步骤或顺序操作要求。

### 游戏内任务的动作门控（已实现）

```json
{
  "type": "task",
  "guide": {"text": "请点击排序；退出请使用教程框。", "layout": "side", "next_button": "hidden"},
  "task": {"timing": "action", "action": {"id": "editor.sort"}, "allowed_actions": ["editor.menu", "editor.view", "editor.inspect"], "success": {"type": "deck_count", "zone": "main", "value": 6}},
  "failure": "sort_cards", "next": "sorted"
}
```

`action` 任务只用于 `in_game`。预期动作匹配稳定 `id` 与可选 `args` 子集；`allowed_actions` 表示为完成任务允许的辅助动作，辅助动作不会代替预期动作推进。允许动作：`editor.sort`、`add`、`remove`、`move`、`inspect`、`search`、`filter`、`rule_set`、`view`、`page`、`menu`、`select_zone`（均带 `editor.` 前缀）。参数支持 `card_id`、`zone`、`source_zone`、`source_index`、`target_index`、`value`；卡牌参数引用真实定义 ID，源区域与索引区分同一 draft 中的副本。

按钮、选牌、输入、切换和拖放在原回调执行前通过门控。错误按钮包括「返回主菜单」只记录 `action_failures`、显示任务失败，并按可选 `Step.failure` 回退；不会执行原指令。`restore_on_failure` 为 true 时恢复入口检查点，默认重试继承现状。正确动作调用原组卡器方法；增删/移动若实际未改变 draft，按真实拒绝处理，不伪造动作成功。新增 `ui_action_accepted` 事件与 `deck_count` 条件（`zone`、`value`、`op: eq/le/ge`）。该界面不支持对局的 phase/life 等条件或规则状态变化等待。

示例中 PC 点击顶部「排序卡组」；Android 切换卡组视图 → 菜单 → 排序。点击返回、保存或增牌会失败且原指令不执行。隐藏指引仍继续判定，恢复按钮留在场景内；退出仅通过教程框完成。

### OpponentRule 的条件触发、阻挡、出牌与启动能力

```json
{
  "strategy": "rules",
  "rules": [{
    "id": "pass_once",
    "event": "step_entered",
    "when": {"type": "priority", "value": 1},
    "action": "pass_priority",
    "max_times": 1
  }]
}
```

`paused` 是默认策略，且不能填写规则。`rules` 在收到事件后按配置顺序匹配状态条件，每 tick 最多执行一项响应，始终以对手座位 1 调用适配器真实提交。规则 ID 必须唯一，`max_times` 为正整数，成功调用次数在内存检查点中保存。无匹配规则且未开启自动响应时保持等待；待处理玩家选择结束后再交还执行权，其他非法操作会报告规则 ID 与引擎拒绝原因。旧的 `action: "pass_priority"` 继续有效，也可写成 `action: {"type":"pass_priority"}`。

`opponent.auto_response: true` 开启基础自动响应，和触发规则共用真实 Gateway。先处理已排队的显式规则及固定响应序列，规则不适用或次数用尽后才自动让过执行权、完成对方调度及待选操作；未配置的阻挡选择默认不阻挡，必须阻挡时选择合法单位。自动响应不消耗触发次数，不代替玩家选择，也不主动出牌或攻击；动画、讲解、答题和录制序列期间仍按原流程暂停。任务重置和检查点包含此设置。

编辑器新建战场默认开启自动响应，在 **任务场景触发器 → 自动响应（无可用触发规则时）** 可关闭，设置随课程保存。试玩旧课程时，缺少此字段的场景在独立试玩副本中默认开启，明确设为 `false` 时保持关闭；试玩不会修改原课程。普通课程入口省略此字段仍保留原有响应方式。专项检查为 `tests/test_tutorial_automatic_response.gd`、`tests/test_tutorial_authoring_ui.gd`。

对手支持指定单位阻挡、多个单位共同阻挡和明确不阻挡。例如，下列配置让对手在玩家的 `student_attacker` 攻击时，用 `enemy_blocker` 阻挡一次，并自动让过战斗中的执行权：

```json
{
  "strategy": "rules",
  "rules": [
    {
      "id": "block_student_attack",
      "event": "state_changed",
      "when": {
        "type": "all",
        "conditions": [
          {"type": "pending", "kind": "block", "owner": 1},
          {"type": "combat_attacker", "alias": "student_attacker"}
        ]
      },
      "action": {"type": "block", "cards": [{"alias": "enemy_blocker"}]},
      "max_times": 1
    },
    {
      "id": "pass_responses",
      "event": "state_changed",
      "when": {"type": "priority", "value": 1},
      "action": "pass_priority",
      "max_times": 32
    }
  ]
}
```

两处别名须在同一战场场景的卡牌配置中定义。省略 `combat_attacker` 条件、只保留 `pending` 条件即可对任意攻击者使用该阻挡决定；也可组合生命、步骤完成、卡牌区域等已有条件。`cards` 必填，每项只接受 `{"alias":"场景实例别名"}`；多个不同别名表示共同阻挡，`cards: []` 表示不阻挡。重复别名、未知别名、直接填写 uid、未知动作字段会在加载课程时被拒绝。

阻挡只在真实引擎产生 `pending.kind == "block"` 且 `owner == 1` 时提交；此时执行权可能仍在玩家，不能用 `priority == 1` 代替阻挡时机。建议监听 `state_changed`，因为进入阻挡选择不一定改变执行权。指定单位须属于真实合法阻挡者集合，提交仍由 Gateway 调用原 `block()`，因此保留横置、不能被阻挡、威吓至少两个单位等规则。不会替换成其他单位；非法阻挡会报告规则 ID 和原因，不消耗成功次数。没有合法阻挡者时原引擎自动不阻挡，教程规则不会额外消耗次数。

泛用让过执行权规则遇到对手的阻挡选择会跳过，让阻挡规则处理，即使让过规则排列在前面或监听另一种事件也不会抢先报错。阻挡条件不匹配或次数用尽时保留选择并等待。讲解和答题期间暂停对手，恢复任务后继续处理排队事件；检查点和任务重置保留或恢复事件、阻挡次数及真实战斗状态。专项验证入口为 `tests/test_tutorial_opponent_block.gd`。

### 攻击触发的阻挡优先级快捷设置

在 **编辑条件／触发器 → 条件编辑器／录制触发** 中，点击 **快捷对策：攻击与阻挡**，选择哪些我方攻击需要阻挡，再勾选需要启用的方案，用 **↑／↓** 调整优先级。攻击范围支持指定单位、我方灵力最高的单位、我方灵力前 x 名（x = 对方场上单位数），以及自定义数值排名。一个触发器包含五种阻挡方案：最大单位、最小单位、尝试联合击杀、所有单位联合阻挡、制作者指定单位阻挡。指定单位支持列表勾选和战场点选，可选择多个单位；场景别名和录制生成实例均可保存。

快捷设置生成 `state_changed` 事件、`combat_attacker` 条件和带 `priorities` 的 `block` 动作。数组由前到后表示优先级，`enabled` 默认 `true`，界面新建时只启用最大单位。每种方案最多出现一次，必须启用至少一种；`cards` 与 `priorities` 不能同时指定。例如：

```json
{
  "id": "block_attack_priority",
  "event": "state_changed",
  "when": {"type": "combat_attacker", "alias": "student_attacker"},
  "action": {
    "type": "block",
    "priorities": [
      {"strategy": "selected", "cards": [{"alias": "enemy_blocker"}]},
      {"strategy": "lethal"},
      {"strategy": "largest"},
      {"strategy": "smallest", "enabled": false},
      {"strategy": "all"}
    ]
  },
  "max_times": 1
}
```

只检查当前合法阻挡单位。最大／最小先比较当前攻击，再比较剩余血量，同值按战场顺序；这两项各选一个单位，威吓不允许单挡时继续检查下一项。联合击杀至少选择两个单位，沿用战斗预估检查先制、防止伤害、守护、已受伤害和不会被消灭，并尝试移除不必要的单位；预估基于当前局面，不预测后续响应或手动伤害分配变化。所有单位方案选择全部合法阻挡者。指定单位不存在、已横置或组合不合法时跳过整个方案，继续按优先级筛选。全部方案不满足则不阻挡；必须阻挡的攻击仍遵循引擎限制，交给后续规则处理。

快捷触发器自动让过这次攻击的对方战斗响应，保留我方操作和伤害分配。场景包含阻挡优先级快捷触发器时，非战斗中的堆叠响应也会在已排队的显式规则处理后自动让过，支持先使用去除牌再攻击；自动让过不消耗阻挡次数，不处理待选操作，不推进空闲阶段。进入实际阻挡选择后才计一次 `max_times`，讲解暂停、检查点和任务重置同时保存／恢复优先级和战斗响应状态。录制一个我方攻击且未指定后续对方响应时，可更新快捷触发器的攻击单位；录制了对方响应则按原录制流程替换成固定响应序列。图形编辑和外层设置均应用后写入课程，取消保留原配置。专项检查为 `tests/test_tutorial_block_priorities.gd` 和 `tests/test_tutorial_condition_editor_ui.gd`。

灵力排名使用 `combat_attacker_rank` 条件，也可直接作为任务成功／失败条件。它检查真实战斗中的当前攻击者，在 `player` 方的场上全部单位中比较当前数值，包含已在战场的自机、横置单位和中途生成实例；不需要绑定具体别名。`key` 可选 `spirit`（灵力）、`power`（攻击力）或 `health`（剩余血量），沿用引擎增益和光环后的数值。范围恰好指定 `count`（正整数前 N 名）或 `count_player`（用该方当前场上单位数作为 x）；x 为 0 时没有单位符合。

“灵力最高”默认 `count: 1, ties: "all"`，包含所有并列最高单位。“前 x 名”默认 `count_player: 1, ties: "field_order"`，数值相同按战场顺序取前 x 个，保证单位数不超过 x。自定义排名在 **条件** 页修改数值、范围来源和同值处理；省略 `ties` 时按战场顺序。双方单位数、攻击者数值均在实际判定时重新计算，响应期间的增益或单位离场也会改变结果。例如，对方有两个单位时，下列规则阻挡我方灵力排名前两名的攻击：

```json
{
  "id": "block_top_spirit",
  "event": "state_changed",
  "when": {"type": "combat_attacker_rank", "player": 0, "key": "spirit", "count_player": 1, "ties": "field_order"},
  "action": {"type": "block", "priorities": [{"strategy": "largest"}]},
  "otherwise": "no_block",
  "max_times": 100
}
```

排名快捷设置默认勾选 **条件不满足或次数用尽时自动不阻挡**，保存为规则的 `otherwise: "no_block"`。从默认单次触发切换到排名快捷设置时，执行上限提升为 100000，供多个攻击单位反复判定；可在 **触发时机** 页调整上限。范围外的攻击自动让过对方战斗响应并提交真实不阻挡选择，不消耗阻挡次数；次数用尽也能继续战斗。此项仅适用于监听 `state_changed`、不限定操作的按优先级阻挡规则。强制阻挡的攻击继续遵守原引擎限制，无法自动不阻挡时留给后续规则。取消勾选则在条件不匹配时等待其他规则或操作。初始场面没有我方单位时，仍可设置排名快捷对策供后续单位使用。专项检查为 `tests/test_tutorial_attack_rank.gd`。

### 条件触发的指定手牌与能力

`OpponentRule.action` 还支持 `cast` 与 `ability`，保留相同的 `event`、`when` 与 `max_times`。例如，将以下规则放进战场场景的 `opponent.rules`，可让对手在取得执行权且玩家生命不高于 10 时，从手牌使用「樱华ノ月」，指定玩家的 `student_unit`：

```json
{
  "id": "cast_sakura",
  "event": "state_changed",
  "when": {
    "type": "all",
    "conditions": [
      {"type": "priority", "value": 1},
      {"type": "life", "player": 0, "value": 10, "op": "le"}
    ]
  },
  "action": {
    "type": "cast",
    "card": {"card_id": "96"},
    "target": {"alias": "student_unit"}
  },
  "max_times": 1
}
```

`card` 必须恰好指定 `card_id` 或 `alias`。定义 ID 只在对手当前手牌中查找，多个副本时固定使用手牌顺序中的第一张；`alias` 精确指定已绑定实例，也必须仍在对手手牌。别名可预先绑定场景牌库中的牌，抓到手牌后即可使用。牌不在手牌、所有权改变、时机不合法或指定目标当前不可选时，跳过该规则。不会从其他区域出牌，也不会代换另一张牌或另一个目标。

指定启动能力使用 `ability`，`source` 必须是场景实例别名，并恰好指定一个 `key` 或 `index`。扩展能力的 `key` 对应原引擎 `available_actions()` 返回的能力键，而不是按钮文案或方法名。下例发动四季映姬的 `exile_grave` 能力，移除指定墓地牌：

```json
{
  "id": "activate_eiki",
  "event": "state_changed",
  "when": {"type": "priority", "value": 1},
  "action": {
    "type": "ability",
    "source": {"alias": "enemy_eiki"},
    "key": "exile_grave",
    "target": {"alias": "student_grave_card"}
  },
  "max_times": 1
}
```

普通启动能力用 `index`，从 0 开始，对应卡牌 `abilities` 中 `实现: "activated_damage"` 的条目，例如 `{"type":"ability","source":{"alias":"enemy_unit"},"index":0,"target":{"player":0}}`。引擎分别通过 Gateway 调用原 `commit_ability()` 或 `commit_extension()`；能力不在对应来源的真实动作列表中时报告配置错误。来源当前不可发动、在错误区域或不能支付费用时跳过。横置、召唤失调、次数、计时和牺牲等限制继续由真实规则检查。

所有出牌和启动能力都在提交前，根据**当前来源、完整目标、模式及 X 值**计算真实费用，再用原 `payment()` 选择合法资源；支付不足时不提交、不扣资源、不横置来源、不消耗 `max_times`、不停止课程。遇到这种跳过时，同一事件仍可匹配后面的让过执行权等备用规则；以后新的匹配事件可以再次尝试。只有真实提交成功才计数。自动支付不启用免费模式，也不绕过额外费用。需要横置来源的普通启动能力会从支付来源中排除该实例，避免同时将它用于支付和能力横置。

两类动作都需要对手执行权；普通牌仍只能在自己的合法时机使用，高速牌按原规则响应。玩家有待完成选择时保留事件，选择完成后再尝试；对手有阻挡等选择时先等待该选择对应的规则。讲解和答题暂停、每 tick 最多一项成功操作、次数限制、检查点和任务重置沿用已有控制器行为。

目标只接受下列声明式选择，不接受原始 uid、epoch 或任意引擎状态：

| 目标写法 | 行为 |
| --- | --- |
| `{"alias":"student_unit"}` | 指定实例，提交时读取当前 uid/epoch；可用于战场或能力允许的墓地等区域 |
| `{"player":0}` | 指定玩家；0 为学员，1 为对手 |
| `{"stack":{"alias":"student_spell"}}` | 指定该卡牌正在堆叠中的使用，或以该实例为来源的能力；须能唯一定位当前堆叠对象 |
| `{"none":true}`，或省略 `target` | 仅选择真实无目标选项；需要指定目标的动作保持等待 |
| `{"alias":"student_unit","mode":"重置"}` | 在同一目标的多个模式中明确选择一个 |
| `{"player":0,"x":2}` | 声明确切 X 值，再按该值检查支付 |
| `{"picks":[[{"alias":"cost_unit"}],[{"alias":"target_unit","mode":"重置"}]]}` | 按真实选牌组顺序指定费用及目标；可加 `selection_id` 区分多种选牌方式 |
| `{"parts":[{"alias":"enemy_unit"},{"alias":"student_unit"}]}` | 指定原规则要求的有序组合目标，例如「天狗ノ晴岚」的己方与对方单位 |
| `{"alias":"student_unit","sacrifice":{"alias":"cost_unit"}}` | 对使用时牺牲一个单位的旧式目标选项，明确指定目标和牺牲来源 |

`mode`、`color`、`x` 和 `selection_id` 可作为真实选项的筛选参数。控制器从当前合法选项中保留完整提交数据，包含规则选牌组需要的附加信息；所选费用、目标数量、不同名限制等仍通过原规则校验。若同一声明对应多个模式或 X 值，会报告规则 ID 与 `action.target` 错误，要求明确选择；不会自动决定未指定的分支。专项验证入口为 `tests/test_tutorial_opponent_actions.gd`。

当前 `OpponentRule` 动作支持 `pass_priority`、`block`、`cast` 和 `ability`；该条件响应控制器尚未实现攻击、其他待选操作、普通 AI 回退或完整对手响应判定。`ability` 负责主动发动启动能力；使用牌后产生的触发能力和进场选择仍按原规则产生。对话步骤的 `sequence` 已支持双方攻击与明确的待选动作，详见固定动作演示一节。

## 校验与检查点

所有课程启动前重复校验，错误包含课程 ID、`steps.<ID>` 或 `scenarios.<ID>` 路径、具体字段和原因。检查未知字段、不存在的注册卡牌/步骤/场景/组件/别名、无效跳转/回退、不支持的条件/动作、重复别名/规则 ID、明显自动跳转环。校验沿成功与失败路径传播当前场景，检查每个可达步骤的别名绑定，不能拿另一场景的同名别名满足引用。自动环检查覆盖自动讲解、进入时判定和等待 `step_entered` 的循环。运行时仍对当前场景绑定做兜底检查；不会按同名卡找替代物。

目录错误在进入教程列表时弹出；单课错误在启动或运行指引里显示。构造场景先在私有候选引擎完成，失败不会替换运行中的局面。

每步入口保存内存检查点。`Runtime.capture()` 包含课程 ID、步骤、已完成步骤、规则图、别名、组件策略、随机状态、对手次数/排队事件和当前步骤事件。恢复会刷新原 UI，并使旧时间线的延迟推进失效。普通游戏存档与教程进度分开；教程目录会另存每个已读步骤的入口检查点，以支持跨重启跳转。弹框隐藏状态、拖拽、临时支付草稿、镜头和动画不属于规则检查点；课程应在稳定交互边界恢复。

任务和等待对话框显示「重置局面」按钮，通过 `Runtime.reset_task()` 恢复当前步骤入口的检查点，回到操作前的规则局面或练习卡组。保留前面步骤的完成进度，恢复卡牌区域、生命、资源、随机状态与对手响应次数，清除当前界面的选牌、支付和动画，并重新显示任务说明。答题任务重置后清除已选答案。讲解步骤、课程完成和执行错误时不显示此按钮。

三类场景的检查点还包含场景类型/配置、临时教学卡组和最近已执行 UI 动作。卡组恢复重建原生界面，实际 draft 恢复为检查点内容；搜索、选牌、视图和滚动位置目前回到初始化状态，未作为教程存档保存。

## 启动

正常启动项目 → **游戏教程** → 选择 **欢迎来到极彩 Multicolor**、**极彩对战的开局**、**学习单位牌**或**初探非符** → **教程目录**。目录按步骤的 `next` 顺序展示指引摘要、已读与未解锁状态；首次只能打开起点，**开始阅读／继续阅读** 打开已到达的最远步骤，**从头阅读** 保留已有进度。只有真正进入过的步骤可以跳转，界面按钮和启动函数都检查限制。教程中的 **教程目录** 按钮返回本课目录。

每步首次进入时保存已读记录和真实入口局面，包括教学卡组、战场、随机状态、对手控制器和此前场景。文件位于设置文件同级的 `tutorial_progress/<课程 ID 哈希>/`，使用压缩二进制检查点及 JSON 已读索引，先写临时文件再替换。回看不覆盖原始入口、不缩减解锁范围；重启后仍可跳转及使用 **上一步**。读取不启用对象反序列化。课程内容改变时以内容指纹隔离不兼容的检查点；旧版本的整课完成标记仍保留，逐步记录从本次阅读开始积累。任务恢复到该步骤的开始局面，尚未完成的操作需要重新执行。

现存课程专项测试入口为 `tests/test_tutorial_t1.gd`、`tests/test_tutorial_opening.gd`、`tests/test_tutorial_mulligan_selection.gd`、`tests/test_tutorial_lily_opponent.gd`、`tests/test_tutorial_lily_ui.gd`、`tests/test_tutorial_t3.gd`、`tests/test_tutorial_t4.gd` 和 `tests/test_main_menu_tutorial.gd`。目录及跨重启恢复专项测试为 `tests/test_tutorial_directory.gd`。

## 教程节点编辑器与功能录制

教程编辑器仅在桌面调试版本开放，发行版和安卓隐藏 **教程编辑器** 与每课 **编辑**，并在 `tutorial_editor()` 入口拒绝直接打开。允许使用时，入口为 **游戏教程 → 教程编辑器**；现有课程行的 **编辑** 可打开该课程。主界面提供节点增删、搜索、节点属性与录制；工具栏提供新建课程、打开、保存、录制及返回。左侧 **教程顺序** 按实际阅读顺序编号，从上到下定义课程流程。选中节点后可按 **上移／下移**，或按住节点约 0.45 秒后拖至目标节点上半部／下半部，插入线标明前后位置；拖到列表边缘会自动滚动。排序同步更新课程起点、成功后的下一步和末尾完成位置，不再单独设置起点与成功跳转。搜索保留课程原序号，移动依据完整课程位置；新增节点插在选中节点之后。排序保留各节点原有场景、录制内容和独立失败跳转；跨场景移动时自动补齐必要的场景来源。打开课程时不改写数据，拖出列表取消或原位放下也不产生修改。任务属性可修改成功／失败条件、所需操作，以及判定时点、指定选择等现有参数；**编辑条件／触发器** 可修改当前场景对手规则的事件、条件、触发动作、响应动作序列和次数上限。所有修改先在独立表单中编辑，应用时校验完整课程。原课程中的演示、答题、组件、随机结果等配置在打开和仅编辑文字时完整保留。

双击左侧节点，或选中节点后点击右侧 **重命名节点**，即可快速修改名称。输入框自动选中原名称；按回车或 **确定** 应用，按 Esc 或 **取消** 放弃。支持中文名称，自动去掉首尾空格；空名称、重名、保留名称和非法字符会在窗口内提示。重命名同步修复课程起点、成功／失败跳转及各处条件中的节点引用，保留原顺序、场景和录制内容。若搜索旧名称会隐藏改名后的节点，应用时清空该搜索并显示选中的节点；保存后重新打开仍保留新名称。

左侧按节点 ID 或指引文字搜索；右侧编辑节点类型、指引、起点、成功／失败跳转和教学场景。战场任务点击 **条件编辑器**，在独立战场预览旁修改条件节点图；卡组／组卡器任务继续使用紧凑表单。两种界面都支持全部满足、任一满足或取反。失败时可恢复该节点的开始状态；同时满足成功与失败时，失败优先。改变一个节点的场景类型会为后续原节点保留原场景来源。

节点指引文字下方的 **节点配图 → 选择节点配图／编辑／更换配图** 打开独立编辑窗口。右侧按名称、编号、别名、颜色或类别搜索，可筛选横卡／竖卡并预览卡图，在 **卡图版本** 明确选择默认卡面或异画，点击 **加入这张卡图**；先在左侧选中已有配图，再点击 **替换选中配图** 即只更换该项。左侧列表显示具体卡名、编号、横竖方向和卡图版本，支持上移、下移及逐项移除；**添加自定义图／更换为自定义图** 可与卡图混排。选择横向、纵向或网格排列并实时预览，点击 **应用配图** 才写入节点，取消保留原配置。节点属性中显示每张配图的名称和排列方式，**移除全部配图** 只清除当前节点配图。配图与节点文字一起保存，**预览当前节点／试验当前任务** 可检查实际指引；改变节点类型、场景或顺序时保留配图。

节点属性的 **初始配置** 显示当前有效场景的自机和卡组张数。点击 **编辑初始自机和卡组**，可切换我方／对方，搜索卡牌、替换初始自机、批量加牌、移除指定副本、一键清空当前区域，以及上移／下移调整牌库抽牌顺序；卡组查看和组卡器场景可分别编辑主副卡组及规则集。也可从已保存卡组 **导入卡组**，勾选是否同时导入自机。战场导入以来源主卡组顺序替换当前一方牌库，保留起始手牌、战场、颜色盘等区域；保留匹配副本的原别名和状态，更换自机保留自机的原别名和状态。窗口说明此场景供多少个节点使用；修改场景起点不会把沿用或恢复进度的节点改成重置场景。所有操作先保留在独立草稿中，**应用初始配置** 校验场景和完整课程后才写入，取消不产生修改；删除课程条件所引用的别名时会显示错误并保留草稿。教学配置随课程 JSON 保存，玩家的已保存卡组保持不变。

战场条件图中点选节点或点击 **定位此条件**，金色箭头指向它检查的卡牌实例、玩家、目标区域或对局阶段；选择组合节点时展示其子条件的检查对象。点击战场卡牌、双方生命按钮或区域可以改选当前条件的对象，其他子条件保留。底部提供初始场景卡牌及当前中途生成实例按钮，便于选择手牌和未展开的牌堆；生成实例显示卡名、所属方和独立编号，使用 `created` 保存引用。卡牌对象、比较方式、阈值和组合关系均可直接修改；在卡牌条件之间切换类型会保留已选实例。

点击 **录制修改条件** 后，使用原生战场操作录制状态变化，可撤回一步或放弃本次录制。**结束录制** 后勾选实际出现的生命、区域、横置／攻击、指示物或战斗时点等条件，再用录制结果替换当前选中的节点；勾选多项会生成全部满足组合。最后点击 **应用条件** 才写入任务。已存在的条件默认采样其当前对象和字段，取消编辑保留原课程；从已有录制的某一边界打开编辑器，会以该真实局面为录制起点，外层动作历史保持独立。

### 在当前编辑器指定中途生成的单位

1. 在桌面调试版进入 **游戏教程 → 教程编辑器**，选中战场任务节点，点击 **条件编辑器**；失败条件也可通过 **修改失败条件** 打开同一界面。
2. 点击 **录制修改条件**，按真实规则使用生成衍生物的牌或能力，让其完成结算，再点击 **结束录制**。若正在 **编辑已有录制**，先定位到生成后的边界，再打开 **修改成功条件**，会直接看到该局面里的生成实例。
3. 选中要修改的条件节点，点击战场上的衍生物，或底部「生成实例 #N · 我方／对方 · 卡名」按钮。也可把节点对象来源设为 **中途生成实例**，再在下拉框选择对应卡名和编号。多个同名衍生物分别选择各自编号。
4. 将类型设为 **卡牌所在区域**、**卡牌横置／攻击**、**卡牌颜色指示物**、**卡牌伤害／计数** 或 **指定攻击者**，配置目标区域、属性和阈值。例如「青蛙横置」选 **卡牌横置／攻击 → 横置 → 是**。金色箭头定位当前实例，底部文字显示预览是否满足。也可以勾选录制结果中的对应实例条件，点击 **用录制结果替换选中条件**；多项条件会组成 AND。
5. 点击 **应用条件**，返回节点后 **保存**，并用 **试验当前任务** 验证任务中的实际生成过程。

条件录制用于选择对象和采样状态；应用条件不会把这一段录制变成自动生成单位的演示。实际任务仍需让玩家、已有动作序列或对手规则完成生成。保存后重新打开条件编辑器，初始预览尚未生成该实例时会显示「尚未生成」，原编号会保留；再次录制同一生成过程即可定位。更改前面的生成动作、生成数量或初始场景后，应重新录制并选择所需实例；自由操作中若创建顺序不固定，建议改用 **区域卡牌数量** 条件按所属方、区域、卡牌定义或类别检查数量。

**编辑条件／触发器** 打开当前场景的规则卡片列表。每条卡片直接显示「何时检查、限定操作、成立条件、对方响应、最多次数」，支持复制、删除与上下排序；同一时机先执行排在前面的可用规则。顶部说明该场景共用的节点数量。点击 **编辑条件与响应** 后，右侧按 **1 触发时机 → 2 条件 → 3 对方响应** 切换，规则摘要和导航固定在顶部，应用／取消固定在底部。触发时机可选择事件、操作种类、操作方与卡牌；条件继续支持战场点选和条件图。对方响应可直接选择让过执行权、指定单位／不阻挡、自动阻挡优先级、指定手牌与目标、异能来源及序号／键，或录制固定响应。

点击 **录制修改触发器**，操作我方触发动作及后续对方响应，结束后选择触发操作并 **用录制更新触发和响应**。触发条件取自该动作刚完成后的真实阶段、战斗时点及待选／执行权；其后连续的对方动作成为响应序列，保留原规则 ID 和次数上限。图形编辑应用后返回规则草稿，点击 **应用设置** 才写入课程；也可点击 **应用并试验当前任务** 验证响应。取消新建触发器不会添加默认规则，取消外层设置保留整份原课程。

每个节点的属性提供 **修改初始场面**。点击后打开该节点的独立布置界面，可直接调整双方卡牌和初始血量，无需录制动作。**应用初始场面** 校验场景及完整课程，再为所选节点建立从起点开始的场景；原共享场景、节点指引、任务条件及已有录制保留，后续未指定场景的节点继续沿用流程。**取消** 丢弃布置草稿，未修改直接应用不增加场景或撤销记录。卡组查看和组卡器节点也能修改各自的教学卡组起点。

**录制** 根据当前节点场景进入真实对战、只读卡组总览或组卡器。卡组和组卡器录制前可点击 **布置教学卡组**，使用独立原生组卡器准备起点；录制前操作不会生成步骤。对战布置时可用双方加卡和原调试拖动调整场面。左键点选双方手牌、战场、颜色盘或区域列表内的牌，再按 **D** 直接删除指定实例，按 **C** 在原所属玩家的同一区域复制一张；复制保留横置、伤害和指示物等初始状态，并建立独立实例及别名。牌库副本插在原牌之后。牌库、墓地、除外及自机区均可通过区域列表操作；套牌自机在任何区域都不能删除，自机区副本可复制、删除并保存。操作不触发抓牌、弃牌、进场或离场效果，也不生成录制动作。右键双方玩家的血量按钮可修改其正整数初始血量；顶部布置栏避让对方血量，电脑手牌自动避让布置栏。文本输入、弹窗、拖动及动画期间不响应 D/C。点击 **开始录制** 后关闭布置删除、复制和血量编辑，修改后的局面成为录制起点。录制期间可撤回动作，重新布置会恢复起点并清空录制。教学卡组只保存在内存中。

布置初始场面或录制前的对战场景时，左键选中战场单位，再按 **P** 切换该实例的 **已过一回合** 状态；战场上的自机也支持。关闭后按刚进场处理，开启后按已过一回合处理，攻击和横置异能仍遵守实际规则，疾行照常生效。单个单位的设置优先于顶部 **单位已在场** 的默认选项，复制时继承且可独立切换，应用、保存重开以及开始录制后均保留。其他区域和非单位卡牌不响应 P；文本输入、弹窗、拖动、动画、录制和回溯期间也不响应。

已有录制的节点显示 **编辑已有录制**。战斗演示和顺序任务通过真实规则重建每个动作前后的内存检查点，保留原动作、预设随机结果及随机状态推进方式；组卡操作任务载入同一场景中连续的任务节点。上方用 **步骤 → 步骤** 表示既定流程，战斗中的攻击、指定目标和阻挡另有带步骤编号的流程箭头。**上一步／下一步**、位置选择框和流程按钮可以追溯任意边界；**播放／暂停** 从当前位置继续动画。仅浏览或播放不会删掉后续录制。

选中一个步骤的起点后点击 **从此步重录**，保留此前的动作并替换该步及后续动作。已有节点的指引、成功／失败条件和失败跳转保留；组卡录制重新应用时复用原节点 ID，缩短录制会修复被移除节点的引用，后继课程仍连接在录制之后。修改录制只发生在独立工作区，点击 **应用到节点** 才修改课程，取消则保留原文档。重录第一个动作可以完整替换片段，**重新布置** 可以重新准备录制起点。

组卡器的加入、移除、移动、查看、排序、搜索、筛选和界面切换等已接受操作会生成各自的功能任务节点，连续输入搜索文字合并为最终一条。卡组总览支持录制查看指定卡牌的指导。录制结果可修改每步指引和成功／失败条件，并删除不需要的录制步骤。**应用到节点** 用第一步替换当前节点，把其余步骤插入原后继节点之前；第一步恢复录制起点，后续步骤沿用实际操作状态。默认失败跳回本步骤并恢复其开始状态，应用后可在节点属性中修改跳转。

例如，在组卡器向主卡组加入「樱华ノ月」（定义 ID `96`），录制会同时生成 `task.action: {"id":"editor.add","args":{"card_id":"96","zone":"main"}}` 和 `task.success: {"type":"deck_count","zone":"main","card_id":"96","op":"eq","value":1}`。另加一张牌、把指定牌加到副卡组、仅查看该牌都不会完成这个任务。`deck_count` 的可选 `card_id` 只统计指定牌，省略时统计整个区域；支持 `main`、`side`、`leader`。`ui_action` 条件以 `action` 对象检查最近已接受的操作，可用于“加入指定错误牌则失败”。功能任务在所有已接受操作后检查失败，只在操作匹配当前所需动作时检查成功。

对战录制结果只提供 **功能指导任务** 与 **动作演示**。功能指导默认要求我方按录制顺序操作，对方动作自动执行；可指定独立成功和失败条件。失败条件在录制动作尚未全部完成时也会检查。取消顺序要求后，玩家可自由操作，对方响应从录制生成，成功须设置具体条件。动作演示自动播放双方动作，结束后显示原节点讲解。

所有节点都可通过工具栏 **试验当前节点** 或节点属性 **试验当前任务／预览当前节点** 启动。试玩直接进入所选节点对应的场景起点，不显示前面的课程步骤；所选节点之前的流程节点仅在私有试玩中计为已完成，以保留完成条件。后续组卡录制任务会在后台还原同段录制中之前的组卡操作，供移出、查看等任务使用。战场从该节点对应的配置局面开始，节点自身的演示和互动序列正常执行；不会自动模拟之前的自由战斗。重置任务恢复当前试玩的检查点，返回保留选中节点和未保存的文档，不写课程完成标记或改写课程起点。保存先检查完整配置和所有场景，再用同目录临时文件替换目标。默认保存目录为 `user://tutorials/`，其中合法课程自动出现在教程列表；同 ID 的本地课程覆盖内置课程展示。录制、取消和预览不改变玩家正式卡组或普通编辑草稿。

相关模块为 `authoring_editor.gd`、`function_recorder.gd`、`recording_ui_flow.gd`、`battle_recorder.gd`、`condition_form.gd`、`condition_graph.gd`、`condition_workspace.gd`、`condition_battle.gd`、`condition_arrows.gd` 与 `condition_capture.gd`。专项测试为 `tests/test_tutorial_authoring.gd`、`tests/test_tutorial_authoring_ui.gd`、`tests/test_tutorial_function_recording.gd`、`tests/test_tutorial_recording.gd`、`tests/test_tutorial_recording_ui.gd`、`tests/test_tutorial_condition_capture.gd` 与 `tests/test_tutorial_condition_editor_ui.gd`。
