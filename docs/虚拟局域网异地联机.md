# 虚拟局域网异地联机

当前断线规则以[卡组分享、观战与回放](卡组分享、观战与回放.md)为准：`.mdeck` 与 `.mreply` 位于 EXE 同目录；观战使用对战端口加1；断线等待期间可随时离开，30 秒后可选择持续等待。

2026-09-20，适用于 multicolor:arena 1.0。

## 是否可行

可行。现有游戏使用 ENet / UDP，通过 IP 和端口连接。只要组网工具让两台电脑的虚拟 IP 可以互相传递 UDP，便能沿用现有联机模块跨不同家庭网络或城市连接，不需要将游戏上架商店，也不需要上传 EXE 到组网服务。

原来的物理网卡与 IP 保持，工具另外提供虚拟网卡和虚拟 IP。ZeroTier 官方明确说明网络可在设备移到另一网络后继续工作，并给出了物理网卡与虚拟网卡同时存在的例子。[ZeroTier 官方组网说明](https://docs.zerotier.com/start/)

## 当前测试建议

先用提供通用虚拟局域网的工具验证。Windows 双机可从 Radmin VPN 的“创建网络／加入网络”流程开始；也可使用 ZeroTier 创建网络并授权两台设备。这里只建议安装网络客户端，不需要安装远程桌面控制端。[Radmin VPN 官方连接说明](https://www.radmin-vpn.com/help/)

1. 双方使用同一版本游戏包，在组网工具中加入同一个私有网络，确认两台设备在线。
2. 房主打开游戏的“联网对战”，监听地址选“所有网卡”，或明确选择工具提供的虚拟 IP。对局端口通常保留47861。
3. 房主创建房间后，将虚拟 IP 和端口告诉另一方。不要发送家庭路由器分配的192.168地址，除非该地址就是组网工具明确分配的地址。
4. 客机在“输入地址加入”里填房主虚拟 IP，端口填47861或房主修改后的端口，点击加入。房主接受申请，双方选卡组并准备。
5. 若自动房间列表为空，继续使用地址加入。广播发现与点对点连接是不同路径，列表为空不能证明虚拟 IP 不可达。
6. 查看房间及战场右上角双方的ms值，再按《局域网双机测试》验证开局、响应、单局投降、BO3、断网恢复。显示的是游戏连接往返时间，已包含虚拟网络的实际路径影响。首次连接应允许本游戏通过相应网络的防火墙规则；仅需要游戏通信，无需关闭整个防火墙。

对局需要虚拟网络中的UDP47861（或所选对局端口）可达；UDP47860只用于房间发现。虚拟地址稳定时可继续使用现有重连；房主地址改变，填写新地址再点击“重连上次房间”。

## 通用对战平台的适用条件

提供虚拟局域网本身即可满足底层需求，但“支持局域网游戏”不等于已经支持任意自制EXE。具体平台需要提供自定义程序／通用房间，或允许游戏使用其虚拟网卡上的UDP。仅支持指定游戏专房、仅代理已识别程序的平台，需要确认其自定义接入能力；当前没有对某一平台做实际适配验证。

例如游侠官方说明其通过虚拟局域网支持非局域网联机，也维护平台支持的游戏列表。这个说明支持技术可行性，但不足以证明本项目已获得其客户端支持。[游侠官方说明](https://pk.youxia.net/wap)

## 延迟和一致性

本游戏由房主统一结算，替换为虚拟网络后，卡牌、BO3、操作去重与重连协议保持不变。网络延迟主要影响提交和确认的等待时间；不会要求客机根据自己的帧率重新计算伤害。

虚拟网络可能建立直接连接，也可能使用中继。Radmin说明无法直连时可建立Relay/TCP连接；ZeroTier指出中继可能增加延迟和丢包。因此不能仅凭“虚拟IP”保证跨省延迟或始终P2P，仍需用双方实际运营商网络测试。[Radmin连接类型说明](https://www.radmin-vpn.com/help/)、[ZeroTier中继说明](https://docs.zerotier.com/faq/relaying/)

这轮未安装任何组网工具、修改系统IP或防火墙，也未进行真实异地连接。可行性结论来自官方资料及本项目IP直连入口；实际网络质量待双机测试。
