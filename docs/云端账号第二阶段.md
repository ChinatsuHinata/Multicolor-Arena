# 云端账号第二阶段

## 功能

当前账号支持设备绑定的自动登录、昵称设置、云端房间及套牌广场身份校验。玩家表新增 `elo INTEGER NOT NULL DEFAULT 1000`：首次部署时为已有账号补齐 1000 分，新账号沿用相同默认值；重复启动不会重设已保存的分数。登录、自动登录及昵称更新返回本人的 Elo，客户端仅在主菜单「玩家账号」的已登录页面显示「我的 Elo」。不公开其他玩家的分数，不提供改分接口，也未接入对战加减分或结算。

## 自助修改密码（本地实现，待部署）

已登录的「玩家账号」页面新增旧密码、新密码及再次确认新密码三个隐藏输入框。三项均符合 8–64 位英文可见字符要求、新密码不同于旧密码且两次新密码一致时，「修改密码」按钮才启用；回车提交也执行相同校验。旧密码的正确性由账号服务验证。

实现参考 SSH 主机 `/home/codex/dual-platform-staging/work/reset_password.py`：使用新的 16 字节随机盐和 310000 次 PBKDF2-SHA256 更新密码，并在同一事务内删除该玩家 PC、安卓的所有会话。昵称、Elo、套牌等账号数据保留。成功后客户端删除本机自动登录凭据、断开当前云端会话并返回登录页；失败则保留当前登录状态。

账号服务复用现有中转的 `action`、`username`、`password`、`nickname`、`token` 字段，依次执行 `pwa`、`pw_set`、`pw_confirm`。客户端在 RSA 密文内提交 128 位随机秘密；旧密码验证成功后，双方用该秘密及服务端返回的随机数派生 120 秒有效的一次性验证票据。票据只出现在后续 RSA 加密请求中，明文响应本身无法授权改密。服务端暂存新密码的盐及哈希，确认匹配后才写库。若期间密码已被其他操作修改，提交会失败。验证票据在服务重启后失效。旧密码失败次数与登录共用 15 分钟内最多 5 次的限制；明文密码不会保存到数据库、文件或日志。

分步请求可容纳含引号、反斜杠的 64 位密码，保持既有 2048 位 RSA 的加密包长度不变。登录／注册请求仅在 JSON 转义后超过长度限制时，使用仍在 RSA 密文内的紧凑密码编码，由账号服务解码并执行原有校验。

本次只读取远端重置脚本，未上传文件、修改线上数据库或重启云端服务。中转协议和中转脚本无需修改。线上启用仍需另行部署新的 `account_store.py` 并发布客户端；未更新账号服务时，客户端提示「账号服务尚未支持修改密码，请等待服务更新」。不要直接运行现有 `relay/deploy.ps1` 来部署此单项改动，因为该脚本还会更新中转及其他服务。

验证入口：`tests/test_account_store.py` 覆盖旧密码、确认、过期、重放、失败限制、原子更新和双平台凭据清理；`tests/test_account_ui.gd` 覆盖双端表单及按钮门控；`tests/run_password_change.py` 使用回环地址和临时数据库运行原有账号流程与 `tests/test_password_change.gd`，验证通过未改动的中转完成修改及重新登录。

## 首阶段记录

下面保留首阶段账号实现及部署记录。

主菜单「玩家账号」可注册、登录和退出显示状态。账号由 3–24 位英文字母、数字或下划线组成，大小写不区分；密码为 8–64 个字符。成功登录后的账号名只保存在本次客户端进程的内存中。目前账号不控制联机、卡组、回放或其他功能，也不自动登录。

客户端将账号请求用固定的服务端 RSA 公钥加密，再通过现有 WebSocket 中转端口 `47862` 发送。中转进程解密后，只把请求转交给本机 `127.0.0.1:47864` 的账号进程。账号进程使用 SQLite `players` 表保存账号、随机盐、PBKDF2-SHA256 密码哈希、注册时间和最近登录时间。原始密码不写入数据库或日志。账号请求含随机数和时间戳，服务端拒绝重放与过期请求，并限制登录失败次数。

## 部署

在项目根目录运行 `powershell -ExecutionPolicy Bypass -File .\relay\deploy.ps1`。脚本需把本地忽略提交的 `relay/account_private.pem` 一同上传；不要单独重新生成公私钥，否则已导出的客户端无法向服务器加密请求。服务会自动建立 `~/.local/share/multicolor-relay/data/players.sqlite3`，账号服务监听回环地址，不需要新增公网端口或防火墙规则。

服务检查：

```bash
systemctl --user status multicolor-account-user.service
systemctl --user status multicolor-relay-ws-user.service
ss -tln | grep -E '47862|47864'
```

备份玩家表时使用 SQLite 的在线备份 API，或先停止账号服务再复制 `players.sqlite3` 及其可能存在的 `-wal` 文件；另行妥善保存 `account_private.pem`。私钥不应放进客户端安装包或版本库。若必须更换密钥，需重新导出使用新公钥的客户端。

## 当前边界

账号密码请求由应用层公钥加密；当前 WebSocket 通道本身仍非 TLS，账号服务响应和对局中转数据没有传输加密。当前账号只供注册登录流程测试，未来若将账号用于匹配、排行榜或资产，应补上完整 TLS、会话认证和相关权限校验。
