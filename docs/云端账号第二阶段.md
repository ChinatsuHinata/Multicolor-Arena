# 云端账号第二阶段

## 功能

主菜单「玩家账号」可注册、登录和退出显示状态。账号由 3–24 位英文字母、数字或下划线组成，大小写不区分；密码为 8–64 个字符。成功登录后的账号名只保存在本次客户端进程的内存中。目前账号不控制联机、卡组、回放或其他功能，也不自动登录。

客户端将账号请求用固定的服务端 RSA 公钥加密，再通过现有 WebSocket 中转端口 `47862` 发送。中转进程解密后，只把请求转交给本机 `127.0.0.1:47864` 的账号进程。账号进程使用 SQLite `players` 表保存账号、随机盐、PBKDF2-SHA256 密码哈希、注册时间和最近登录时间。原始密码不写入数据库或日志。账号请求含随机数和时间戳，服务端拒绝重放与过期请求，并限制登录失败次数。

## 部署

在项目根目录运行 `powershell -ExecutionPolicy Bypass -File .\relay\deploy.ps1`。脚本需把本地忽略提交的 `relay/account_private.pem` 一同上传；不要单独重新生成公私钥，否则已导出的客户端无法向服务器加密请求。服务会自动建立 `~/.local/share/multicolor-relay/data/players.sqlite3`，账号服务监听回环地址，不需要新增公网端口或防火墙规则。

服务检查：

```bash
systemctl --user status multicolor-account-user.service
systemctl --user status multicolor-relay-ws-user.service
ss -tln | grep -E '47862|47864'
```

备份玩家表时使用 SQLite 的在线备份 API，或先停止账号服务再复制 `players.sqlite3` 及其可能存在的 `-wal` 文件；另行妥善保存 `account_private.pem`。私钥不应放进客户端安装包或版本库。若必须更换密钥，需重新导出使用新公钥的客户端。

## 验证

本地账号服务启动后，以 `tests/test_account.gd` 对本机 WebSocket 入口测试注册、重复账号、错误密码与登录；同脚本可用 `-- --server ws://8.137.122.187:47862` 测试 ECS 公网入口。`tests/test_account_ui.gd` 检查客户端表单。原有 `tests/test_relay.gd` 验证房间中转功能。

## 当前边界

账号密码请求由应用层公钥加密；当前 WebSocket 通道本身仍非 TLS，账号服务响应和对局中转数据没有传输加密。当前账号只供注册登录流程测试，未来若将账号用于匹配、排行榜或资产，应补上完整 TLS、会话认证和相关权限校验。
