# 特效开发方法论

适用范围：香霖堂三个特效品类——**单位入场特效**（`entrance`）、**闪卡特效**（`foil`）、**符卡使用特效**（`spell`）。

一句话原则：**一个特效 = 一个目录 + 一份清单 + 一个脚本，其余仓库文件一律不动。**
加第十个特效和加第一个特效的工作量必须一样，验收也只围绕这一个特效。

当前未内置特效，三个品类的框架与本体接线保留。下文 `example_entrance` 是清单格式示例；创建新特效时按需新建 `definitions/`、`modules/`、`assets/` 目录。

---

## 1. 三层结构与改动边界

```
fx/
  definitions/<特效id>.json     清单：唯一给特效命名的地方
  modules/<特效id>/effect.gd    模块：唯一写这个特效行为的地方
  assets/<特效id>/*.png         素材：生图产物，只在模块里按文件名取
tests/test_fx_module.gd         验收：遍历 fx/，与本体无关
fx/fx_showcase.gd               预览：单独把某特效放进迷你台面
```

| 层 | 允许改 | 不允许改 |
| --- | --- | --- |
| 开发一个新特效 | `fx/definitions/<id>.json`、`fx/modules/<id>/`、`fx/assets/<id>/` | 其它任何目录 |
| 改已上线特效 | 同上三者之一 | 其它特效目录、本体脚本 |
| 改基底（罕见） | `fx/fx_*.gd`、`fx/categories/*.gd` | 任何 `<id>` 目录 |
| 接本体（一次性） | 每个品类一处接线（第 6 节） | 一次接入后不再为特效改本体 |

**本体（`scripts/duel_table.gd`、`scripts/duel_view.gd`、`scripts/rules/*`）不出现任何特效 id、材质名或节点名。** 本体只认识 `fx_bridge.gd` 的三个方法。

## 2. 清单（definitions）

一份清单只描述"这个特效是谁、属于哪类、脚本在哪、预算多久"，不描述视觉。

```json
{
  "id": "example_entrance",
  "category": "entrance",
  "name": "入场特效示例",
  "description": "一句话给商店与日志看。",
  "script": "res://fx/modules/example_entrance/effect.gd",
  "budget_ms": 620,
  "priority": 10,
  "free": true,
  "asset_dir": "res://fx/assets/example_entrance/",
  "params": { "petals": 14, "color": "#f9c9d8" }
}
```

规则（`fx/fx_manifest.gd` 强制校验，非法清单进 `errors` 而不是崩溃）：

- `id` 必须与文件名一致，2–40 位 `a-z0-9_`；
- `category` 只能是 `entrance` / `foil` / `spell`；
- `script` 必须在 `res://fx/modules/` 下——不允许把模块塞进本体目录；
- `budget_ms` 50–5000，缺省 700；`foil` 用不上（持续播放）；
- `free: true` 表示默认启用；付费特效用 `shop_product` 或由商品上的 `fx` 字段绑定（第 7 节）；
- **视觉参数只放 `params`**，调色、数量、半径都在这里调，不改脚本。

## 3. 生命周期契约（所有模块统一）

模块继承对应品类基类，只实现 `_build()` 和 `_frame(delta)`：

```
configure(def, ctx) → start() → [advance(delta) …] → stop()
```

- `start()`：基类创建唯一 `holder`（`Fx_<id>`），调用 `_build()`，校验节点数 ≤ 64，然后 `_frame(0)`。
- `advance(delta)`：基类推进 `elapsed` 再调 `_frame(delta)`；超过 `budget` 自动 `stop()`。
- `stop()`：`holder.queue_free()`，`done` 信号只发一次。
- **时间只来自 `elapsed`。** 禁止 `Time.get_ticks_msec()`、禁止在着色器里用 `TIME` 当主时钟；需要动画进度就传 uniform。原因：回放、断线重连、测试手动步进都要求同一时刻同一帧。
- **随机只来自 `rng`**，基类已用 `id:uid` 播种。禁止 `randf()` 全局随机。
- **无素材必须能跑。** `texture()` 找不到文件时记 warning 返回 `null`，模块退回纯几何/纯色；这是"生图素材晚到"时仍能合并的前提。

## 4. 三个品类的挂载契约

### entrance 单位入场特效

- `parent` 是花牌视觉根（`duel_table` 的 `card_<uid>`），模块**只加子节点**，随卡牌一起移动/缩放/消失，不需要额外清理。
- 尺寸一律用 `ctx.card_size`（当前 `1.95 × 2.72`），不写死世界坐标。
- 不修改 `Face` / `Halo` / `Outline` / `SummoningMist` 的材质，不改 `Hit` 碰撞。
- 视觉建议：向外扩散或向内收拢的环、光柱、落地尘，y 轴 0 ~ 0.02 层。
- 时长基准 400–700 ms；超过 700 ms 会拖延出场节奏。

### foil 闪卡特效

- 也挂在花牌视觉根下，但**只允许在 y ∈ [0.019, 0.055] 加平面**：0.018 是召唤失调雾层，0.06 是颜色六边形，越界会遮住规则信息。
- **不替换 `Face.material_override`**，不读写卡图纹理，不碰输入与费用显示。
- 持续播放：`budget` 不做自动收尾，由卡牌离场时的节点释放或 `stop()` 结束。
- 相位统一用 `phase()`（0..1 循环，周期取 `params.cycle`，默认 2.4 s），不要用 TIME。
- 视觉建议：斜向扫光带、边缘流光、细密噪点闪；强度上限建议 ≤ 0.6 透明度，否则读牌变难。

### spell 符卡使用特效

- `parent` 是舞台的 `FxLayer_spell`，**不是**卡牌节点——符卡此刻可能已翻面或移位。
- 位置用 `ctx.center`（符卡世界坐标），尺寸用 `ctx.card_size`；模块自己把中心应用到 `holder`。
- 不碰堆叠、不碰结算、不碰卡牌节点，纯表现。
- 时长基准 700–1200 ms；这是"读一秒演出"的位置，可以比入场长。

## 5. 素材：用 Codex 生图

产出物只落在 `fx/assets/<特效id>/`，模块通过固定文件名引用。

**文件名约定**（模块按名取，换图不改代码）：

| 文件名 | 用途 | 规格 |
| --- | --- | --- |
| `ring.png` | 环/光圈 | 512×512，正中，边缘完全透明 |
| `sprite.png` | 单片花瓣/火星/符文 | 256×256，居中，留 8 px 透明边 |
| `sweep.png` | 扫光条带 | 1024×256，水平可平铺 |
| `burst.png` | 爆点/闪白 | 512×512，中心径向 |

生图提示词必须写死的约束：

1. 纯黑或透明背景（加法混合吃黑底，透明底也行），**不要背景、不要文字、不要边框**；
2. 单一元素、居中、占画布 60–80%，四周留白；
3. 不画运动模糊、不画拖影——运动由模块的 `elapsed` 驱动，烘焙进图会和程序动画打架；
4. 颜色只用清单里的主色系：樱 `#f9c9d8`、绯 `#e2604f`、金 `#e9c175`、白 `#fbf2f0`；需要其它色靠 `tint` 乘；
5. 环状素材必须径向对称，条带素材必须左右无缝。

流程：生图 → 落到 `fx/assets/<id>/` → 跑 `Godot --headless --path . --import` 生成 `.import` → 跑该特效的验收（第 8 节）。**`.import` 由 Godot 生成，不手写。**

## 6. 本体接线（已完成，之后不再动）

接线已在 2026-10-24 落地并验收通过（`tests/test_fx_integration.gd`）。**下面是实际写法，不是草案。**

### 6.1 `scripts/duel_table.gd` —— 舞台与三个调用点（共 4 处，约 30 行）

**(a) 字段与接线方法**（放在 `var unknown_material` 之后）

```gdscript
const FxBridge=preload("res://fx/fx_bridge.gd")
var fx
var fx_products: Dictionary={}
var fx_seen: Dictionary={}
var fx_face_seen: Dictionary={}

func attach_fx(products: Dictionary={}) -> void:
 fx_products=products.duplicate(true)
 if fx==null:fx=FxBridge.new()
 fx.attach(self)                 # FxStage 作为台面的子节点
 fx.set_products(fx_products)

func set_fx_products(products: Dictionary) -> void:
 fx_products=products.duplicate(true)
 if fx!=null:fx.set_products(fx_products)

func show_spell_effect(uid: int) -> Array:
 if fx==null:return []
 var card=duel.find_card(uid)
 if card.is_empty():return []
 var node=visuals.get("card_"+str(uid))
 var center=node.global_position if is_instance_valid(node) else zone_position("palette",card.get("owner",local_seat))
 return fx.spell_resolved(node,CARD_SIZE,{"uid":uid,"card_id":card.card_id,"center":center})
```

**(b) 入场**：在 `sync()` 里 `var node=visuals[key]; node.show()` 之后

```gdscript
if fx!=null and d.uid>0 and d.zone=="field" and d.get("group","")=="unit" and not fx_seen.has(d.uid):
 fx_seen[d.uid]=duel.revision
 if fresh and animate:fx.unit_entered(node,CARD_SIZE,{"uid":d.uid,"card_id":d.card_id,"owner":d.owner})
```

`fx_seen` 保证一个 uid 只播一次：分页移出再回来不重播，读档直接落位不播（没有动画就没有入场）。

**(c) 闪卡**：紧随其后

```gdscript
if fx!=null and d.uid>0:
 var face_key=str(d.card_id)+":"+str(d.get("art_id",""))
 if fx_face_seen.get(d.uid,"")!=face_key:
  fx_face_seen[d.uid]=face_key
  fx.card_face_built(node,CARD_SIZE,{"uid":d.uid,"card_id":d.card_id,"owner":d.owner})
```

`face_key` 含异画 id，所以换异画会重挂一次；同卡重渲染不会叠加。

**(d) 符卡**：由 `show_spell_effect()` 收口（上面 a 段），`duel_view` 只调这一个方法。

### 6.2 `scripts/duel_view.gd` —— 两处

**(a)** `table.build(...)` 之后立刻一行：

```gdscript
table.attach_fx(battle_products)
```

**(b)** `configure_shop_products()` 末尾补一行，处理"重开一局时台面已存在"：

```gdscript
if is_instance_valid(table):table.set_fx_products(battle_products)
```

**(c)** `commit_local()` 里，`commit_cast` 成功分支：

```gdscript
var cast_uid=local.uid if local.get("action","")=="" or local.get("action","")=="cast" else -1
var error=engine.commit_extension(...) ...
if error.is_empty():
 engine.paid_cast_uid=-1;local={}; selection=[]; picker.reset(); message=""; close_debug()
 if cast_uid>0 and engine.cards.get(engine.find_card(cast_uid).card_id,{}).kind=="符卡":table.show_spell_effect(cast_uid)
else: message=error
```

只在提交成功后触发：代价不足、目标非法、被反制都不演出。

### 6.3 接线的三条硬约束

1. **只传 `node` / `card_size` / `uid` / `card_id` / 可选 `center`**；不传引擎对象、不传结算数据、不传 buff。
2. **本体不出现任何特效 id、材质名或节点名**。台面只认识 `fx.unit_entered` / `card_face_built` / `spell_resolved` 三个方法。
3. **接线完成后，新增/删除/改色/换图都不应再动这两个文件。** 如果某次需求逼着你改接线，先问是不是品类选错了（例如"符卡在卡面里发光"其实是 `foil` 不是 `spell`）。

### 6.4 接通验收

```bash
Godot --headless --path . --script tests/test_fx_integration.gd
```

真开一局，只测"本体到 fx/"这一段：台面挂上 `FxStage`、清单零错误、单位入场触发一次且重渲染不重播、卡面挂上闪卡且层高合法、符卡提交后落到 `FxLayer_spell` 并按预算自释放、单位离场后挂在其上的模块随节点失效、未装备的付费特效应保持关闭（当前 21 项全过）。

与单特效验收的分工：`test_fx_module.gd` 管"这个特效本身对不对"，`test_fx_integration.gd` 管"本体有没有把它接上"。改本体接线时跑后者，改特效时跑前者。

## 7. 与香霖堂的关系

- 商品在 `data/shop.json` 里声明 `category`（`entrance` / `spell` / `foil`）与 `battle_effect`。
- 特效默认 `free: true`（不挡路地先上）；要卖钱的加 `shop_product: "<商品id>"`，或在该商品上写 `"fx": "<特效id>"`。
- 启用判定集中在 `fx_registry.enabled(category, products)`：`free` ∪ 已装备商品。**判定只读 `battle_loadout()` 冻结的快照**，与现有表情同理，中途改装备不影响本局。
- **联机说明**：现有 `net/shop_entitlements.gd` 只为 `MCA:leader_emotes:<商品>` 验签，特效商品暂不参与联机校验。未扩展之前，联机对局中特效按本机 `free` 与本地装备显示，不视为权威。要扩展时在商品签名域加一个 `MCA:fx:<商品>` 前缀，并同步改 `relay/server.gd:802`；这属于一次性的协议改动，不是特效开发任务。

## 8. 验收：只围绕单个特效

```bash
# 1. 本特效
Godot --headless --path . --script tests/test_fx_module.gd -- --only=example_entrance
# 2. 全量（防止新增清单破坏别的特效）
Godot --headless --path . --script tests/test_fx_module.gd
# 3. 缩进
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/check-gdscript-indent.ps1
# 4. 视觉（非 headless）
Godot --path . --script fx/fx_showcase.gd -- --only=example_entrance --png=work/fx/entrance.png
# 5. 只在改了本体接线或 fx/fx_*.gd、fx/categories/* 时才跑
Godot --headless --path . --script tests/test_fx_integration.gd
```

第 5 条不属于单特效验收：加一个新特效时**不用**跑它，只在动基底或本体接线时跑。

单特效验收清单，每条都必须能对照代码或截图核对：

- [ ] 清单能过 `Manifest.validate`，`id` 与文件名一致；
- [ ] `_build()` 建出的节点 ≤ 64，全部在 `holder` 下；
- [ ] `start()` 到 `stop()` 全程无本体文件引用（测试会 grep `duel_table` / `duel_view` / `scripts/rules` / `CARD_SIZE` / `Time.get_ticks`）；
- [ ] 时间只用 `elapsed`，随机只用 `rng`；
- [ ] 缺素材时降级为纯几何，不报错、不空白；
- [ ] 到 `budget` 自动收尾，`holder` 被释放，父节点无残留；
- [ ] `foil`：所有平面 y ∈ [0.019, 0.055]，不替换 `Face` 材质；
- [ ] `spell`：挂在 `FxLayer_spell`，中心来自 `ctx.center`；
- [ ] 同一特效跑两次画面一致（确定性）；
- [ ] 预览截图里能看清卡面（不被特效盖住读牌信息）；
- [ ] Git 改动只落在 `fx/definitions/<id>.json`、`fx/modules/<id>/`、`fx/assets/<id>/`。

验收 **不看** "其它特效还在不在""全仓库测试全绿"——那是合入前的整体回归，不属于单特效验收。

## 9. 接到任务时的固定动作

1. 判断品类（entrance / foil / spell），选错会导致后面全部返工；
2. 写清单，定 `params` 的初值；
3. 写 `effect.gd`，先只用纯色几何跑通验收，再谈生图；
4. 跑单特效验收 + 预览截图，确认读牌不受影响；
5. 需要素材时按第 5 节规格调 Codex 生图，落盘、导入、再跑一次单特效验收；
6. 全量 `test_fx_module` + 缩进检查，提交。

任何一步发现要动本体，先停下来确认品类或是否真的需要新接线。

**接线已完成（2026-10-24）**：三个品类的本体接线按第 6 节落地，`tests/test_fx_integration.gd` 使用内存清单与无视觉内容的品类基类验收，不要求游戏内置测试特效。此后特效开发任务**不涉及** `scripts/duel_table.gd`、`scripts/duel_view.gd`、`fx/fx_bridge.gd`；只有品种本身要新增第四个品类（不是新特效）时才需要再动接线。
