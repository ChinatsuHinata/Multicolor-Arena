# 仓库文件与本地数据

Git 仓库保留游戏源码、卡牌和美术资源、公共预设、教程、联机服务、测试、导出工具及开发文档。玩家数据和工具生成的文件保存在本机，不随代码上传。

## 公共源与个人数据

- `data/preset_decks.json` 是四套官方预设的共享来源。编辑器首次运行缺少旧存档时从这里生成卡组；导出插件只从这里选取预设，再加入内置的蕾米 AI 卡组。
- `deck/`、`replay/`、`training/` 和 `saves/` 中的卡组、回放、训练记录、设置及身份属于本机。已有旧卡组迁移逻辑保留，不用复制同事的存档来启动项目。
- `work/`、`output/`、`outputs/`、`tmp/`、构建包、聊天附件、Python 缓存和备份不入库。`work/.gdignore`、`saves/.gdignore` 保留，防止 Godot 导入生成内容。
- 两个 `recourse/MulticolourOnline*` 目录是旧 Unity 发行包，仅保留本地；当前游戏继续使用 `recourse/数据库/`、异画、卡背和桌垫等源素材。
- `tts_mod/` 保留 Python 构建工具和 Lua 模板；TTS 存档、机器路径清单和报告由工具生成，不再上传。
- `.godot/`、安卓 SDK/JDK、导出模板和本地安装工具不入库。按 `Godot环境.md` 准备工具链，资源大文件仍需 Git LFS。
- Godot 的 `.uid` 和素材 `.import` 配置是共享源文件，必须保留。`data/account_public.pem`、`data/update_public.pem` 是运行公钥；私钥及签名文件只保存在本机或部署环境。

## 提交前检查

```powershell
python tools/check-repository-hygiene.py
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/check-gdscript-indent.ps1
git diff --cached --stat
```

第一项检查索引中是否仍有被忽略的本地文件，并检查运行源、公共预设及测试夹具没有被忽略。新增测试源码和明确的 `tests/support/` 夹具可以提交；截图、日志、语料和临时结果应放入 `work/`。不要用 `git add -f` 绕过个人数据和密钥的忽略规则。

本地 AI 训练和 TTS 工具依赖自己准备的回放、训练语料或外部存档；这些输入不是运行游戏的前置条件。

## 从旧仓库更新

这次清理取消了旧个人数据文件的 Git 跟踪。当前维护机器通过 `git rm --cached` 保留了本机文件；其他已有工作副本在拉取前应先备份自己的 `deck/`、`saves/`、`replay/` 和 `training/`，拉取后按需恢复到相同位置。干净检出会删除被上游取消跟踪的旧文件，不能把旧 Git 历史当作个人数据同步机制。

本次只清理当前分支，不重写历史。历史提交中的旧产物仍可恢复，因此 GitHub 的历史仓库体积不会随本次清理立即缩小。
