# 公告系统

Windows 和 Android 主菜单右上角的信封图标打开公告邮箱。红点表示存在未读公告；邮箱按版本从新到旧展示，点击公告查看正文，关闭或返回邮箱后仍保留内容。

发行客户端首次进入主菜单时，按顺序推送最新公告版本中尚未展示或阅读的公告，推送记录按公告 ID 保存。再次启动、自动登录、返回主菜单或安装没有新增公告的补丁，都不会重复推送已展示或阅读的旧公告。PCK 下载、安装后仍使用当前运行版本，完全退出并重新启动、补丁生效后才接收新公告。启动提示、其他弹窗或账号恢复期间会等待，恢复对局时则等到返回主菜单再显示。

公告内容维护在 `data/announcements.json`，随 Windows／Android 完整包和 PCK 补丁一起发布，使用现有的 `data/*.json` 导出规则。发布新内容时，在 `announcements` 中追加一项，填写独立且稳定的 `id`、与 `project.godot` 一致的 `version`、发布日期 `date`、标题 `title` 和正文 `body`，保留历史条目。客户端只接收不晚于实际运行版本的条目；新版本未添加独立内容时保留公告原版本及已读、推送状态，不创建副本。首次安装仍可接收最近一组公告，中途退出或更新后只继续其中尚未展示或阅读的公告。

加载存档时会将旧客户端按补丁版本生成的公告副本合并回原公告 ID，并合并各副本的已读和推送记录，清理邮箱中的重复条目；已撤下公告的副本和收据也会清理。目录明确声明的独立 ID 保持独立，真正新增的公告仍正常推送。迁移结果自动保存。

1.2.8.5 使用两条独立的新公告：先介绍比赛入口、报名与签到、瑞士轮及四强赛程、对局赛制、成绩确认与主办方裁定，再介绍匹配奖励与群聊，并保留群聊配图。两条公告发布日期均为 2026-10-14，首次进入菜单依次弹出，关闭第一条即显示第二条。`id` 标识独立内容，`order` 控制同版本推送顺序；已读和推送状态按 ID 分别保存。中途退出只会在下次启动补推未展示的那条。

1.2.8.11 新增两条公告，发布日期为 2026-10-18：先介绍官卡「幻想ノ秋司」及规则更新，再介绍 Windows／Android 的 MOD ZIP 导入、启用、更新与联机配置要求。两条公告使用独立 ID 并依次推送，历史比赛及匹配奖励公告继续保留在邮箱中。客户端完成补丁安装并重启后接收这组新公告。

1.2.8.12 修正自动登录完成时重建菜单会提前关闭公告的问题。首次公告在自动登录检查后推送；阅读中的公告在菜单刷新时保留同一窗口，第二条等待玩家关闭当前窗口后再推送。沿用原公告 ID 和阅读记录，不新增重复公告。

1.2.8.14 新增响应时限公告，发布日期为 2026-10-21：每个响应窗口最多等待 240 秒，超时自动选择「不响应 / 继续」并释放优先权；仅在最后 30 秒显示倒计时。选择目标、支付费用和打开设置不会重置计时；主要阶段自由行动、起手调度及结算中的必要选择不计入响应窗口。公告使用独立 ID，历史公告继续保留。

1.2.8.15 新增独立公告 `release-1.2.8.15-response-forfeit`，发布日期为 2026-10-21：联机响应超过 240 秒时，超时者整场判负；同步最终结果后释放双方连接、观战监听及房间，匹配和比赛先等待服务器结算确认。保留真实局分并清理旧房间恢复记录，人机仍自动不响应。未登录时不显示段位徽章和「毛玉级 2」，登录后显示账号段位。新公告替代上一版联机超时处理的说明，已读过旧公告的玩家也会收到。

目录的 `removed_ids` 撤下旧版以版本号为 ID 的 `1.2.8.4`、`1.2.8.5` 两条公告。加载用户存档时先删除这些旧快照及对应收据，再导入两条新公告；旧推送不会进入弹窗或邮箱，新公告也不会被旧的同版本已读记录挡住。迁移后的记录自动保存。

首次公告附带群头像、群名、群号及二维码。`image` 指向 `assets/announcements/matching_rewards_group.jpg`，`image_region` 使用 `[x, y, 宽, 高]` 指定原图的白色卡片区域；界面使用原图区域显示，保留二维码原始像素。PC 阅读界面左侧显示文字，右侧完整显示群卡片；安卓配图位于正文下方，可滚动查看。图片优先读取导入资源，没有导入文件时直接读取原始 JPG；双端导出规则包含公告 JPG 原文件。邮箱中的历史公告也保留配图。已经保存过的同版本公告会补上配图，保留原有推送和已读记录。

公告快照、已读状态和推送记录保存到用户数据目录的 `announcements.json`，覆盖安装及 PCK 更新不会删除。编辑器使用 `saves/announcements.json`；默认不自动弹公告，可以通过邮箱预览，专项测试设置 `announcement_push_in_editor=true` 验证推送。

邮箱左侧提供「未读」「已读」标签，默认打开未读。附带铜钱的公告即使已打开，只要当前账号尚未领取奖励，仍在未读列表中，邮箱入口和该公告继续显示红点；打开并成功领取后才进入已读。普通公告打开后即为已读。领取收据按账号缓存并保留到重启，登录或切换账号后同步服务端领取状态，主菜单每分钟检查新公告；自动推送记录独立保存，未领铜钱不会导致旧公告反复自动弹出。

1.2.9 新增两条独立公告，发布日期为 2026-10-25：`release-1.2.9-changelog`（`order: 0`）汇总相对已发布 1.2.8.15 基准的界面、安卓操作、支付、卡牌、人机、任务、商店、赛事、教程及联机改动；`release-1.2.9-ranked-fair-play`（`order: 1`）重申严禁小号喂分和与他人串谋长期喂分，查实后本赛季禁止段位匹配、清空段位成绩并公告。历史公告和已读记录继续保留。

这两条公告各设置 `coins: 10`。玩家登录后在正文底部点击领取，每个账号每条公告限领一次，合计 20 铜钱。奖励沿用 `relay/community_store.py` 的服务端入账与去重记录，不以本地已读状态作为领取依据。发布时须将同一份 `data/announcements.json` 同步到社区服务的 `community_data/announcements.json` 并由服务初始化导入；仅更新客户端不能建立服务端领取条目。

公告领取的等待、成功、失败及未登录提示直接显示在领取按钮上方。请求期间只禁用领取按钮，不重建正文、重置滚动位置或抢走焦点；失败后可原地重试，关闭公告后到达的回包不再弹窗。原先的原生独占结果弹窗可能被公告的顶层画布遮挡，同时拦截整个客户端输入，表现为点击领取后卡死；客户端源码已移除该领取流程中的原生弹窗。领取是否成功仍以服务端收据和余额为准，重试不会重复发奖。
