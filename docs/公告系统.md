# 公告系统

Windows 和 Android 主菜单右上角的信封图标打开公告邮箱。红点表示存在未读公告；邮箱按版本从新到旧展示，点击公告查看正文，关闭或返回邮箱后仍保留内容。

发行客户端在每个实际生效版本首次进入主菜单时推送一次公告。同版本再次启动、自动登录或返回主菜单不会重复推送。PCK 下载、安装后仍使用当前运行版本，完全退出并重新启动、补丁生效后才推送新版本公告。启动提示、其他弹窗或账号恢复期间会等待，恢复对局时则等到返回主菜单再显示。

公告内容维护在 `data/announcements.json`，随 Windows／Android 完整包和 PCK 补丁一起发布，使用现有的 `data/*.json` 导出规则。发布新内容时，在 `announcements` 中追加一项，填写与 `project.godot` 一致的 `version`、发布日期 `date`、标题 `title` 和正文 `body`，保留历史条目。客户端只接收不晚于实际运行版本的条目；新版本未添加独立内容时会沿用最近一条公告，并为新版本单独记录推送状态。

1.2.8.5 使用两条独立的新公告：先介绍比赛入口、报名与签到、瑞士轮及四强赛程、对局赛制、成绩确认与主办方裁定，再介绍匹配奖励与群聊，并保留群聊配图。两条公告发布日期均为 2026-10-14，首次进入菜单依次弹出，关闭第一条即显示第二条。`id` 标识独立内容，`order` 控制同版本推送顺序；已读和推送状态按 ID 分别保存。中途退出只会在下次启动补推未展示的那条。

目录的 `removed_ids` 撤下旧版以版本号为 ID 的 `1.2.8.4`、`1.2.8.5` 两条公告。加载用户存档时先删除这些旧快照及对应收据，再导入两条新公告；旧推送不会进入弹窗或邮箱，新公告也不会被旧的同版本已读记录挡住。迁移后的记录自动保存。

首次公告附带群头像、群名、群号及二维码。`image` 指向 `assets/announcements/matching_rewards_group.jpg`，`image_region` 使用 `[x, y, 宽, 高]` 指定原图的白色卡片区域；界面使用原图区域显示，保留二维码原始像素。PC 阅读界面左侧显示文字，右侧完整显示群卡片；安卓配图位于正文下方，可滚动查看。图片优先读取导入资源，没有导入文件时直接读取原始 JPG；双端导出规则包含公告 JPG 原文件。邮箱中的历史公告也保留配图。已经保存过的同版本公告会补上配图，保留原有推送和已读记录。

公告快照、已读状态和推送记录保存到用户数据目录的 `announcements.json`，覆盖安装及 PCK 更新不会删除。编辑器使用 `saves/announcements.json`；默认不自动弹公告，可以通过邮箱预览，专项测试设置 `announcement_push_in_editor=true` 验证推送。

