# 云端自动匹配

云端首页的「开始自动匹配」进入服务端队列，「取消匹配」或离开页面会撤回请求。客户端需要登录，同一账号只能参加一场房间或匹配；匹配仅在规则指纹一致的客户端间进行。

匹配面板可以切换「排位模式 · 官限」「休闲模式 · 无限制」和「娱乐模式」，保存上次选择。休闲模式显示「休闲模式」，使用无限制规则、50 张主卡组和 BO1 换备牌，不限制对手段位；双方必须选择相同模式才会配对，队列人数也按所选模式统计。入队后锁定模式和卡组，切回排位时会清除不符合官限的已选卡组。休闲对局正常结束、投降或断线判负均保留胜者和回放，但不改变段位、星数、连胜或 Elo，也不产生段位统计记录。断线及重启恢复保留本场模式和规则。

「娱乐模式」下另行选择「探索幻想乡」或「探索幻想乡全随机版」，分别保存大模式与娱乐玩法。双方自动使用对应的 50 张固定卡组，无需选择个人卡组，也不能换备牌；准备后选择先后手，单局结束即完成整场。娱乐玩法之间及与排位、休闲分别隔离队列，人数按当前玩法统计；不限制段位，仍要求客户端规则指纹一致。公开房间支持观战，断线或重启恢复保留固定卡组、战场及本场玩法；正常结束、投降和断线判负均保存胜者，但不改变 Elo、段位、星数和连胜，也不纳入段位统计。

全随机版的拜访、探索、旅行包、活动分别从单位与自机、非角色符卡、道具与结界、角色符卡卡池随机抽取三张不同名的牌，再选择一张加入手牌。每次从剩余卡池等概率抽取一张，并排除所有同名牌；不足三种牌名时仅提供现有的不同名选项。不按费用或颜色筛选，没有费用保底、自机加权、高速加权、X 费加权、稀有度或单卡概率修正。抽到的牌仍按正常对战规则使用；固定自机保留任意自机能力，四张寻找牌保留原有费用、使用时机与极彩。

云端与局域网创建房间时，先选择「娱乐模式」，再选择娱乐玩法。自建娱乐房间内，房主可在准备阶段切换玩法，双方固定卡组同步替换并清除准备状态；双方准备进入先后手选择后锁定。自动匹配房间始终锁定入队时的玩法，客机与观众可查看选择。

匹配服务读取账号数据库中的段位，不接受客户端填写的段位，也不使用 Elo 选择对手。每秒集中处理等待请求，优先选择同大段位组合，再按大段位差从小到大选择；大段位差相同时优先小段位更接近的组合，再处理等待更久的玩家。开始即可匹配同一大段位的全部级别；任一方等待满 20 秒后允许上下各 1 个大段位，此后每满 20 秒再扩大 1 个大段位，最多上下各 4 个大段位，覆盖全部段位。例如天狗级 3 与天狗级 1 可立即匹配，等待 20 秒后可匹配妖精级和妖怪级的全部级别。星数不影响匹配，贤者的不同排名视为同一大段位。等待页展示已等待时间、当前大段位范围及队列人数；「排位规则」弹窗集中展示五种段位样式和匹配说明。

匹配成功后双方使用现有房主入房提示音提醒，沿用「入房提醒音量」和静音设置。重复响应、座位同步和重连不会再次播放。

排位与休闲对局固定使用「BO1 换备牌」和 50 张主卡组；排位使用官限规则集，休闲使用无限制规则集。排位登记与换备牌均按官限校验，包括主副卡组的同名张数上限及线下独占卡禁用；卡组自身的规则集标签不能改变匹配规则。双方登记卡组并准备后公开自机，房间准备页和换备页展示对方自机卡图及其异画；桌面右键、安卓长按一秒可查看完整详情。允许最多换入三张备牌，再次准备后投骰选择先后手。匹配成功后的登记、公开自机换备牌及选择先后手阶段，玩家准备页隐藏「离开房间」和顶部返回入口；换备编辑器的「返回」只回到准备页，继续保留本场匹配。观众、自建房间及匹配结束后的退出入口照常可用。

匹配面板提供「公开匹配房间」隐私开关，默认开启，并保存上次选择。入队后锁定本次设置；双方都开启时，匹配房间显示在云端房间列表内，仅提供观战入口，自动分配六个观战位。任一方关闭时，本场为私人房间，不显示在列表，知道房间标识也不能加入观战；隐私设置不影响对手配对、规则和计分。等待页展示本人选择，匹配成功后双方展示服务端确认的本场公开状态。未确认私人设置的旧服务端响应会取消本次匹配并提示更新服务端，避免私人选择被忽略。原玩家重连仍使用保留的对战位，并恢复本场隐私状态。匹配房间不允许额外对战玩家、换位或再来一场。结算成功或取消计分后，服务端通知双方及围观者并立即删除房间；玩家可在结果页返回云端重新匹配，围观者收到最终胜者或取消结果并停止重连。

正常结束由双方报告相同的整场胜者后结算。休闲模式仅保存结果；排位模式的 Elo 使用 K=32、400 分尺度的期望胜率，两名初始 1000 分的玩家产生 1016／984 的结果。结算及双方分数在 SQLite 的同一事务内持久化，重复报送或服务重试不会重复改分。不同报告取消计分。

匹配中途断线保留原玩家的座位 60 秒，原账号可重连；开始对战后，一方超过恢复时限仍未连接，服务端判其负并结算。开战前中断或双方都离线时取消匹配，不计分。匹配服务重启导致房间丢失时，客户端结束该匹配，不能将它恢复成公开房间。

自动匹配的参赛玩家在断线后持续尝试恢复原对局，战场和房间页不提供“不再等待，离开对局”，也不再显示本机的“继续等待”选择。原匹配的恢复信息在配对时即保存，网络波动、关闭程序及设备退出不会主动清除；重新启动并自动登录或手动登录成功后，优先连接尚未结束的原匹配，房主加载保存的权威战况，客机恢复原座位与同步信息。服务器确认结算或匹配房间已失效后停止恢复。恢复记录按登录账号隔离，自动恢复期间优先处理对局，补丁检查等待匹配结束后进行。上述行为不延长服务器的 60 秒恢复时限；普通自建房间及观战仍使用各自原有的离开操作。

退出后点击「开始匹配」表示结束原匹配：同一设备的旧匹配连接会被释放；开战前取消计分，开战后仍有对手在线则按离场判负，保留已确认的结果。服务端等待旧结果写入数据库，再自动把新请求加入队列，使用更新后的分数和段位；清理期间取消请求不会留下幽灵队列。原房间的重连请求继续享有 60 秒恢复时间。

Elo 只通过登录、本人连接的认证或结算响应返回。房间列表、双方共享房间状态、对手信息均不包含 Elo；结算后本人的账号页面更新分数。普通自建房间不计入 Elo。

## 1.2.8：段位匹配自机采集与统计

此项已随 1.2.8 正式发布，中转与 `match_character_log.gd` 已同步部署。新增统计从上线后的公开战况采集自机，不需要重新登记卡组。

中转在房主发送给对战客机的现有公开房间数据中提取双方自机，仅在对局进入对战或完成状态后记录一次。UDP／WebSocket 分别写入 `data/match_leaders-enet.jsonl` 和 `data/match_leaders-websocket.jsonl`，避免两个进程争用同一文件。记录只含匹配 ID、双方自机 ID、记录时间和来源；统计读取 SQLite 最终结算结果，取消与未结算匹配不计入。部署包不包含或覆盖 `data/` 历史记录。

在 VS Code 的「终端 → 运行任务」选择「云端: 下载段位匹配自机使用率与胜率」。任务沿用当前 Windows 账户加密保存的 SSH 私钥口令，将带北京时间的 CSV 及 `段位匹配自机统计_最新.csv` 写入 `D:\云端报告`，同时保留 TXT 说明与 JSON 快照。CSV 使用 UTF-8 BOM，包含自机 ID、名称、使用次数、使用率、胜负场数、胜率、统计起始版本与时间、数据时间，可直接用 Excel 打开。

筛选起始版本为实装自机采集的 1.2.8；服务端上线起点为北京时间 `2026-10-11T01:06:14+08:00`，依据该次发布的中转启动日志（UDP／WebSocket 均开始监听）。创建时间早于该起点的对局全部忽略，不计入样本、缺失数或覆盖率分母；`--since` 可进一步缩小范围，不能回退到采集上线前。双方必须有段位结算记录，排除休闲、娱乐、取消、未结算和无效结果。

「云端: 下载段位前20名报告」同样输出带北京时间的 CSV 及 `段位前20名_最新.csv`，包含序号、昵称、段位、段位序号、星数、Elo、段位对局数、胜场、负场、胜率、账号 ID、账号名和数据时间，并保留 TXT／JSON。玩家胜率按胜场除以段位对局数计算，显示两位小数；统计数据库保留的全部已结算且双方有段位结算记录的历史对局，不受自机采集上线时间限制。取消、未结算、休闲、娱乐、旧版仅 Elo 结算及无效结果不计入，投降和断线判负采用服务器最终结算。无段位对局显示“暂无对局”；重新导出未保存胜率数据的旧快照时显示“未采集”，需重新下载获取统计。两项任务的终端输出均直接显示 CSV 路径。

使用率按自机出场次数占已确认双方自机的参赛次数计算，每场两次；胜率按获胜次数除以出场次数计算。异画归并到规范自机 ID，镜像对局计两次使用、一胜一负，断线判负采用服务器最终结算。报告注明采集上线后范围内的自机覆盖率；范围内数据不全时仅展示样本内统计，零样本显示无法统计。采集上线前未保存自机的历史对局不再作为统计缺失。
