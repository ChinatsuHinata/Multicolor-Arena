# 云端自动匹配

云端首页的「开始自动匹配」进入服务端队列，「取消匹配」或离开页面会撤回请求。客户端需要登录，同一账号只能参加一场房间或匹配；匹配仅在规则指纹一致的客户端间进行。

匹配服务读取账号数据库中的 Elo，不接受客户端填写的分数。每秒集中处理等待请求，优先选择分差最小的可匹配组合；分差相同时先处理等待更久的玩家。初始允许分差 100，任一方等待满 60 秒后放宽到 200，此后每满一分钟再增加 100。

匹配成功后双方使用现有房主入房提示音提醒，沿用「入房提醒音量」和静音设置。重复响应、座位同步和重连不会再次播放。

对局固定使用「BO1 换备牌」、官限规则集、50 张主卡组。登记与换备牌均按官限校验，包括主副卡组的同名张数上限及线下独占卡禁用；卡组自身的规则集标签不能改变匹配规则。双方登记卡组并准备后公开自机，房间准备页和换备页展示对方自机卡图及其异画；桌面右键、安卓长按一秒可查看完整详情。允许最多换入三张备牌，再次准备后投骰选择先后手。

匹配房间显示在云端房间列表内，仅提供观战入口，自动分配六个观战位；原玩家重连仍使用保留的对战位。匹配房间不允许额外对战玩家、换位或再来一场。结算成功或取消计分后，服务端通知双方及围观者并立即删除房间；玩家可在结果页返回云端重新匹配，围观者收到最终胜者或取消结果并停止重连。

正常结束由双方报告相同的整场胜者后结算。Elo 使用 K=32、400 分尺度的期望胜率，两名初始 1000 分的玩家产生 1016／984 的结果。结算及双方分数在 SQLite 的同一事务内持久化，重复报送或服务重试不会重复改分。不同报告取消计分。

匹配中途断线保留原玩家的座位 30 秒，原账号可重连；开始对战后，一方超过恢复时限仍未连接，服务端判其负并结算。开战前中断或双方都离线时取消匹配，不计分。匹配服务重启导致房间丢失时，客户端结束该匹配，不能将它恢复成公开房间。

Elo 只通过登录、本人连接的认证或结算响应返回。房间列表、双方共享房间状态、对手信息均不包含 Elo；结算后本人的账号页面更新分数。普通自建房间不计入 Elo。

## 验证

- `test_match_queue.gd`：近分优先、等待边界、逐步放宽、账号／版本隔离、撤回及去重。
- `test_ranked_relay.gd`：匹配房间与双方响应固定官限、仅观战列表、自动分配及释放观战位、固定对战座位、报告一致性、结算去重、结束清理、本人分数、断线判定及恢复限制。
- `test_match_store.py`：SQLite 迁移、事务结算、重启保留、期望胜率和公开账号接口隔离。
- `run_cloud_matchmaking.py`：启动隔离的回环账号服务与 WebSocket 服务，执行 `test_cloud_matchmaking.gd` 的真实匹配、官限禁卡与三种限二卡拒绝、换备牌、对战、重连与持久化结算流程；使用空闲端口 48045／48046，不连接公网。
- `test_room_join_sound.gd`：PC／安卓音量设置、匹配双方提示、静音及重复事件抑制。
- `test_matchmaking_ui.gd`：PC／安卓匹配入口与等待页的固定官限说明、匹配初始化不接受其他规则、等待进度、取消、两人准备页面及结算后的返回操作。
- `run_cloud_matchmaking.py --simulation-only`：六名不同 Elo 的真实认证客户端同时排队，验证 1000／1010、1080／1170 近分优先；1400／1600 实际等待一分钟后配对。隔离的 `matchmaking_simulation_relay.gd` 仅暂缓初始合批，以保证六人同时进入队列，不修改匹配算法、认证或一分钟计时。日志保存在 `work/cloud-matchmaking/simulation-test.log`。

服务部署包必须同时包含 `server.gd`、`match_queue.gd` 和新版 `account_store.py`。`deploy.ps1` 与 `deploy-deck-plaza.ps1` 已包含这项依赖；客户端需要同步更新 `lan_transport.gd`、`lan_session.gd`、`lan_lobby.gd`、`main.gd`。
