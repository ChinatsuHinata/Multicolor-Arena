# 阿里云中转首阶段

## 范围

两个客户端连接同一个中转服务。默认使用 TCP/WebSocket，也可将服务器地址改为不带 `ws://` 的形式，使用 UDP/ENet。房主创建随机 12 位房间码，客机输入服务器地址与房间码；服务只配对这两个连接并原样转发数据包。房主客户端仍是规则权威端：它审核入房、执行规则、保存恢复记录，并向客机发送各自可见的状态。服务器不加载卡牌、计算胜负或保存对局。

局域网直连功能仍在。云中转默认地址为 `ws://8.137.122.187:47862`，可在建房页修改。`172.30.67.189` 是私网地址，不能作为跨公网玩家的入口。

## 阿里云 ECS 部署

目标机器需要 Linux 版 Godot 4.7.2 可执行文件。只复制本目录中的 `project.godot` 与 `server.gd`；不需要上传客户端、卡牌数据或存档。`codex` 账号没有 sudo 权限，使用 `multicolor-relay-user.service` 和 `multicolor-relay-ws-user.service` 两个用户服务，分别监听 UDP 与 TCP 的 47862 端口；`multicolor-relay.service` 是管理员部署 UDP 时的系统服务模板。

默认 WebSocket 入口需要在 ECS 安全组添加 **入方向 TCP 47862**，并由管理员在 UFW 放行该 TCP 端口。只供固定来源测试时，两处规则均可限制为玩家公网 IP `/32`；若任意公网 IP 的玩家都可加入，则安全组的 TCP 47862 来源设为 `0.0.0.0/0`，UFW 执行 `sudo ufw allow 47862/tcp`。现有 UDP 47862 规则可保留，但不影响 TCP 入口。不要保留排障时临时添加的 `0.0.0.0/0` UDP 安全组规则。无需为对局开放 TCP 47861，SSH 端口只供管理员使用。

以 `codex` 登录后，将 Godot 放在 `~/.local/bin/godot`，将 `project.godot`、`server.gd` 放在 `~/.local/share/multicolor-relay/`，再执行：

本机已有 SSH 私钥时，可在项目根目录运行 `powershell -ExecutionPolicy Bypass -File .\relay\deploy.ps1`。脚本上传中转代码与两个用户服务文件，远端 `install-user.sh` 通过 Godot 官方下载地址取得 4.7.2 Linux 版（仅在 `~/.local/bin/godot` 尚不存在时），并启动两个服务。脚本不会读取或输出私钥正文；直接在本机交互式终端运行时会分别为上传和远端启动提示私钥口令。

```bash
mkdir -p ~/.config/systemd/user
cp multicolor-relay-user.service ~/.config/systemd/user/
cp multicolor-relay-ws-user.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now multicolor-relay-user
systemctl --user enable --now multicolor-relay-ws-user
systemctl --user status multicolor-relay-user
systemctl --user status multicolor-relay-ws-user
journalctl --user -u multicolor-relay-user -n 50 --no-pager
ss -tln | grep 47862
```

安装脚本会尝试 `loginctl enable-linger codex`。本次 ECS 上已返回 `Linger=yes`；若在其他机器上失败，用户服务在该用户完全登出后可能停止，需要管理员开启驻留。

管理员部署可将文件复制到 `/opt/multicolor-relay/`，再执行：

```bash
sudo install -d -m 755 /opt/multicolor-relay
sudo install -m 644 project.godot server.gd /opt/multicolor-relay/
sudo install -m 644 multicolor-relay.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now multicolor-relay
sudo systemctl status multicolor-relay
sudo journalctl -u multicolor-relay -n 50 --no-pager
```

两个服务成功启动的日志分别含 `Multicolor relay listening on UDP 47862` 和 `Multicolor relay listening on TCP/WebSocket 47862`。在客户端的「联机对战」中，房主点击「云端建房」，看到「中转房间已就绪」后复制房间码；客机在相同服务器地址下点击「凭房间码加入」；房主接受申请后选卡组、准备和对局。房主恢复对局使用「恢复房主对局」，客机使用「重连上次房间」。服务器重启会清空内存中的房间；房主客户端重新登记房间码后客机可重连。

本机集成验证：先运行 `godot --headless --path relay --script server.gd -- --transport websocket --port 47872`，再从另一终端运行 `godot --headless --path . --script tests/test_relay.gd -- --server ws://127.0.0.1 --port 47872`。不加 `--transport websocket` 则测试 UDP。两种模式均通过房间码、审核入房、卡组同步、断线重连、由房主结算与胜负同步测试。

2026-09-29 部署状态：ECS 上两个用户服务均已启动，`ss` 显示 TCP 与 UDP 47862 均在监听。管理员已将 TCP 47862 在 UFW 与安全组开放给任意公网 IP。放行后，两套本机客户端再次经 ECS 公网 WebSocket 完成 21 项联机检查，包括房间码、审核入房、断线重连、房主本地结算和结果同步。公网 UDP 测试包未到达 ECS，原因尚未定位；目前客户端默认使用 WebSocket。尚未用两个不同公网出口的实体设备验收。

## 客户端文件

已导出版本 `1.2.5.1` 的更新客户端：Windows 文件位于 `builds/cloud-relay-2026-09-29/Windows/`，必须将 `MulticolorArena.exe` 与 `MulticolorArena.pck` 放在同一目录；Android 调试 APK 位于 `builds/cloud-relay-2026-09-29/Android/MulticolorArena-debug.apk`。两端的 518 个 JSON 和 36 个核心脚本已做交叉校验。旧安装包没有此次云中转入口，需要换用本次导出的客户端。

## 当前限制

本阶段使用普通 WebSocket 或 ENet，公网传输尚未加密。房间码与房主确认只控制加入资格，不提供传输保密性，也不防御恶意房主。现阶段适合测试数据验证；正式对外开放前应接入经验证的加密传输并做公网双机验收。云中转暂不提供观战，局域网观战照常可用。
