# 模组能力接口 v4

v5 增加 `cast_now(ref, free=false)` 与 `target_tax` 查询，继续兼容 v1–v4 包。使用这些功能的包须声明 `api:5`，旧客户端会拒绝加载。

- `cast_now` 在当前结算中立即提供一次可放弃的使用选择，复用引擎声明、支付、入堆叠及响应流程。`free:true` 不支付牌的颜色值，但仍须满足角色、合法目标及附加费用；拒绝或错过选择后不保留使用许可。引用包含 UID、epoch 和区域，失效引用无效。
- `target_tax` 查询包含 controller、targets（声明中的引用列表）、layer、value，返回任意颜色值附加费用的数值修正。引擎对符卡、启动和触发能力统一计费，相同来源在一次查询中只应用一次；选牌费用组不应当作目标。
- testmod 1.1.1 修正融合炉、两根棒及圣白莲：棒不再替代空牌库抓牌；御制棒创造红绿3/3/2御柱；圣白莲的第一张X牌可选择加倍，对手指定她额外支付任意两点颜色值。
- 魔法「紫云ノ兆」先按声明X支付（可移除指示物抵绿），结算时按最终X选择对抗中的符卡；圣白莲加倍后使用加倍X，无匹配符卡时无效果。

v4 增加绯红永夜扩充需要的通用能力，继续兼容 v1–v3 包。使用以下新增命令或查询的包必须声明 `api:4`，旧客户端会拒绝加载。

- `extra_prepare` 常驻数值查询：包含 controller；每个来源可 add 一个额外准备阶段。在正常准备阶段开始时固定本回合的额外次数；额外准备阶段只重复准备阶段事件，不进行重置、颜色盘增长或抓牌阶段。
- `character_permission` 布尔查询补充角色约束；`cast_fast` 布尔查询允许普通牌在执行权时使用。二者不会绕过目标、费用或 action_lock。
- `free_cast` 布尔查询按“不支付颜色值”使用规则处理（包括 X=0）。`phase()`、`colors(ref)` 分别返回当前阶段与当前颜色，均为只读查询。
- `damage(ref, amount, result_key="")` 可记录实际造成的伤害；后续步骤用 `result(key)` 查询。防伤排序暂停、伤害队列与存档恢复保留结果，防止的伤害不计入。
- `fight(first, second)` 进入现有强制战斗判定，保留先制、吸血、防伤与战斗响应；目标失效时不开始战斗。
- `force_leader(ref, count)` 强制印刷的可触发自机能力，不要求该单位当前获得自机能力；不会执行常驻、替代或启动能力。内置吸血鬼自机及模组 `role:leader` / `forced:empty_event` 触发已接入。
- `tokens(owner, card_id, count)` 创造本包登记的衍生物（单步最多100个），复用衍生物进场、战场格、种族、能力及网络卡牌定义。
- `mill(owner,count)`、`shuffle_deck(owner)` 使用现有磨牌规则与权威 RNG；洗牌结果可保存恢复。
- `grant_cast(ref, discount=0, free=false, zone="")` 授予本回合指定墓地或移除区实例的使用许可；discount 是任意颜色值的总减费，沿用既有减费分配和支付。zone 省略时使用当前区域，也可对堆叠来源预授予进入墓地后的本回合使用许可；显式墓地再用不会被通用墓地使用规则自动改为除外。该许可仍保留角色、时机及目标约束。
- `linked_enter(ref, anchor)` 将目标进场，并将其区域版本与战场 anchor 绑定；anchor 离场时牺牲仍在同一战场版本的单位。该单位先离场再进场时，旧绑定不再影响它。
- `end_turn()` 立即结束回合，移除对抗中的牌、清空能力和战斗，再进行正常清理；跳过结束阶段开始触发。
- 印刷关键词 `唯一` 限制同名永久物使用及效果进场；`极彩` 现在也通过通用常驻关键词查询授予，沿用原有支付界面。

示例扩充位于 `examples/testmod/scarlet_moon.gd`，专项为 `tests/test_scarlet_moon.gd`。完整包 `output/testmod-1.1.0.zip` 包含原13张、新增11张可构筑牌及1个不可构筑蝙蝠衍生物。

v3 增加空牌库欠抽数量的批量道具选择，继续兼容 v1、v2 卡包。使用 `recover_draw` 的卡包必须声明 `api:3`，旧客户端会拒绝加载，避免把未识别的批量替代误当作无操作的抓牌取消。模组卡名加载时统一使用日文书名号「」及片假名ノ；无前缀卡名自动补齐书名号，原名称保留为检索别名。

v2 为可信 GDScript 扩展提供符卡、启动、触发、常驻修正及限定变化类型的替代接口；继续兼容 v1 清单。旧卡继续走原来的实现；模组通过注册表分发，使用已有组卡、选择、支付、堆叠、反制、触发排序和网络命令。

这是有边界的规则接口，不是 GDScript 安全沙箱。只安装自己信任的脚本。脚本不得绕过上下文直接访问引擎、文件、网络、全局随机数或其他模组；不可信作者上传需要另行设计受限指令格式。

## 安装与示例

在设置 → 模组中点击「导入模组文件…」，选择 ZIP 模组包。`manifest.json`、脚本、卡牌和资源可直接放在 ZIP 根目录，也可以统一放在第一层模组文件夹中。通过校验后安装到本地 `mod/<模组ID>/`：PC 为 EXE 同目录，开发运行时为项目根目录，安卓为应用可写数据目录。原 ZIP 保留在原位置，日常运行使用本地安装的文件。

导入时检查 ZIP 路径、大小写冲突、CRC、清单、接口版本、脚本入口、卡牌定义及图片。遇到相同 ID 时，自动比较清单中的 `version`：新版通过校验后完整替换旧文件并保留启用状态，同版和旧版拒绝覆盖。数字版本按段比较（`1.10` 高于 `1.9`，`1.2` 等同 `1.2.0`），支持多段数字、可选 `v` 前缀及 `-beta.1` 等预发布后缀；正式版高于同数字的预发布版，`+build` 不影响先后。不能识别的版本格式、ID 大小写变化、多个副本冲突及内置模组均不自动替换。旧外部目录登记升级后迁移到本地安装目录，保留外部源文件。非法、缺失或损坏的文件也拒绝。ZIP 不支持加密、分卷、ZIP64 或符号链接；压缩包至多 256 MiB、2048 项，单文件至多 64 MiB，解压总量至多 512 MiB。安装或配置保存失败时回滚，保留之前的模组、配置和卡库。

新导入的模组默认停用，勾选并点击「应用选择」后立即更新组卡库。点击返回时，若勾选状态有未应用变化，会提示「保存／不保存／取消」；保存成功后才返回，失败时留在页面并显示原因。导入、更新及页面重排保留其他未应用勾选。每项旁的「删除」经确认后移除本地安装文件及登记，并立即卸载对应能力和卡牌；旧外部目录和链接仅移除登记，原文件保留，原 ZIP 也保留。更新和删除会刷新规则及卡图库，无需重启。选择保存在游戏可写根目录的 `mods.json`，导出包不包含此配置和本地 `mod/` 文件夹。已有外部目录配置继续兼容；有活动房间时必须先退出房间再导入、删除或保存选择。加载时固定脚本与卡牌 JSON，编辑磁盘文件后需要重新应用选择。

`examples/testmod/` 是模组源文件，导出时排除；可打包后导入。本机已安装副本位于项目 `mod/testmod/`，完整模组 ZIP 为 `output/testmod-1.1.1.zip`。牌文约定见包内 `README.txt`。

随项目提供的 `mods/example.cards/` 默认停用，包含三个代表能力：

| 文件 | 验证的链路 |
| --- | --- |
| `top_three.gd` | 查看牌库顶三张、私密选择入手、再次选择放回顺序、恢复后继续 |
| `grave_blast.gd` | 红色费用、横置、弃牌额外费用与伤害目标一次提交；响应和反制 |
| `last_word.gd` | 离场前属性与来源区域版本快照；返回战场后原触发继续结算 |

测试辅助包 `tests/support/mod_second/` 提供独立的新符卡脚本和卡牌。它通过同一注册入口接入，无需引擎、界面或网络的卡名分支。

组卡和联机建房时选择“模组”规则集，模组卡牌仅在该规则集下允许构筑。模组规则集沿用无限制的常规张数与同名牌限制，可搭配 BO1、BO1 换备牌或 BO3；换备流程和胜负判定由所选赛制决定。局域网与云端手动房间均要求先启用模组，玩家和观众必须启用相同包集合、版本、API版本及内容哈希，路径可以不同。普通规则集房间与自动匹配拒绝模组卡组，普通权威引擎排除模组定义。原 `mods/example.cards/` 的启动清单方式继续保留，默认停用。没有模组下载或云端分发，也未制作新的游戏发行包。

## 清单与绑定

```json
{
  "id": "my.cards",
  "version": "1.0.0",
  "api": 1,
  "enabled": true,
  "abilities": {
    "blast": {
      "script": "blast.gd",
      "kind": "activated",
      "role": "main",
      "zones": ["field"],
      "text": "支付红1并横置：对目标造成2点伤害。",
      "parameters": {"伤害倍率": {"type": "integer", "required": false}}
    }
  },
  "cards": ["blast.json"],
  "state": {"uses": {"scope": "turn", "visibility": "owner"}}
}
```

包 ID、局部能力 ID 和实例键分别至多 64 字。包 ID 和局部能力 ID 不含 `/` 或 `:`；实例键不含 `:`。包和能力 ID 不能重复。文件路径必须位于包目录内。清单 `parameters` 支持 integer / number / string / boolean 及 required；范围、互斥和额外字段检查由 `validate` 完成，参数不会自动填默认值。

卡牌沿用现有 JSON 格式，`卡牌ID` 必须以包 ID 加 `/` 开头：

```json
{"实现":"mod","实例键":"main_1","参数":{"能力":"my.cards/blast","伤害倍率":1}}
```

同张印刷卡的实例键必须唯一。运行时身份还包括能力 ID、授予后相同绑定的出现序号、来源 UID 与 epoch。重新进场后，旧声明键不能发动新实例。复制和授予通过已有卡牌定义复制机制保留绑定；普通的能力复制保留独立的结算帧。

`kind` 接受 `spell` / `activated` / `triggered` / `static` / `replacement`，后两类要求清单 `api: 2`。`role` 为 `main` 或 `leader`，后者使用现有自机能力授权查询。启动支持 field / grave / hand / leader；符卡必须使用 `zones: ["stack"]`、`role: "main"`，每张卡至多一个 spell 结算入口，可以同时绑定其他种类。没有 spell 入口的模组时符由引擎完成进场及计时X，仍参与现有计时变化和离场规则。多个X颜色用 `可变费用: "黄+黑"` 表示，各颜色分别支付相同的X。

触发描述还需 `events`、`optional` 及 `forced`：

```json
{"kind":"triggered","role":"main","zones":["field"],"events":["self_leave"],"optional":false,"forced":"empty_event"}
```

事件包括 `self_enter`、`self_leave`、`self_exiled_from_deck`、`cast`、`targeted`、`phase`。区域可为 field / grave / hand / leader / stack / deck / exile / palette（启动不允许 stack）。`cast` 额外提供 card、controller、x；`targeted` 提供声明者 controller；`phase` 提供 phase、active。牌库除外事件在移动后发出，source 是除外后的实例，after 是移动前快照。没有通用伤害或任意区域变化事件。`once_per_turn: true` 在生成自然或强制触发时占用该来源能力实例的本回合次数。离场事件在最终去向确认后发出，保留离场前来源；自机返回和衍生物消失仍由引擎处理。`forced: "empty_event"` 允许“使主要触发能力触发”按 `event.type == "forced"` 结算，此时没有自然事件的收件者；`skip` 明确表示无事件时不可强制触发。不得假造原事件目标。现有触发禁止和排序规则仍适用。

## 脚本入口

脚本必须继承 `RefCounted`，构造函数不能要求参数，各入口的参数数量须符合下方接口。每次调用创建新的脚本实例。成员变量不能保存局内进度；不要使用 await、闭包或脚本对象保存结算状态。

```gdscript
extends RefCounted

func validate(params: Dictionary) -> String:
 return "" # 或返回可读的参数错误

func describe_action(ctx, params: Dictionary) -> Dictionary:
 return {"timing":"priority", "cost":{"红":1}, "tap":true,
         "options":ctx.damage_targets()}

func resolve(ctx, frame: Dictionary, answer: Dictionary) -> Dictionary:
 ctx.damage(frame.target, 2)
 return {"done":true}
```

触发能力另外实现 `collect_triggers(ctx, event, params) -> Array[Dictionary]`，每个字典代表一份独立触发的初始 `frame.data`，返回空数组表示不触发。事件和来源都是副本。强制触发直接创建空事件帧，不调用自然事件收集函数。

查询入口不能发出操作；上下文会拒绝命令。所有查询数据是独立副本。查询可能因界面、AI、网络投影反复执行，必须无副作用且确定性一致。

`describe_action` 中：

- `timing` 为 `priority` 或 `main`，后者要求自己的主要阶段、空堆叠且无战斗。
- `cost` 是现有颜色费用字典；`tap` 由引擎检查横置与召唤失调。
- `options` 使用现有选择格式：无目标 `[{"none":true}]`、目标引用、带 `mode` 的选项，或 `selection` 分组。
- 启动额外费用为 `extra_costs: [{"kind":"discard", "group":0}]`，或 `sacrifice`；相应 selection 组必须有 `cost: true`。每个费用组选牌须由一个费用操作支付，不可标记普通目标来回避目标规则。
- 普通符卡的颜色费用在卡牌 JSON 中声明。v1 不支持模组符卡／触发额外费用；这两类入口不能返回 cost、tap 或 extra_costs。

选择组结构为 `{pool: [...], min: 1, max: 1, title: "选择目标"}`；确认值使用 `{selection_id: "...", picks: [[...]]}`，并保留该选项的模式字段。不要使用旧卡特有的 selection_id、私有分支字段或非序列化数据。候选不足可以保留空 pool：声明时不提供该选项；复制／改目标时引擎能替换已支付的费用组并重新选择目标。

声明提交重新生成规格，检查来源实例、所有选牌、费用、目标限制和资源冲突，之后才支付。取消本地草稿不支付；入堆叠后被反制不退费。客户端传递能力实例键和选择，不传函数名、步骤或引擎状态。

## 上下文与结算帧

查询：`source()`、`controller()`、`ref(card)`、`card(ref)`、`cards_in(owner, zone)`、`top(owner, count)`、`stat(ref, key)`、`damage_targets()`、`state(key)`。`card` 检查 UID 和 epoch；`frame.source.mod_stats` 是来源快照的攻击力、血量、灵力，离场触发取离场前数值。

命令：`damage(ref, amount)`、`draw(owner, count)`、`move(ref, zone)`、`sacrifice(ref)`、`reorder_top(owner, refs)`、`set_state(key, value)`。移动目的地限 hand / grave / exile / palette；不提供直接写战场、堆叠或卡牌字典。牌库重排仅允许重排当前顶部同一批牌，不改变其他牌的位置。

命令先缓存在上下文中。`resolve` 返回后，引擎验证整个操作列表再按顺序执行。查询不会看到本次尚未执行的命令。需要根据这些操作的结果继续查询时，返回 `{"continue":true,"step":下一步,"data":{...}}`，操作完成后引擎调用下一步。最多 128 个步骤，每步最多 100 个操作。

需要玩家选择时返回：

```gdscript
return {"step":1, "data":{"remaining":refs}, "choice":refs}
```

`frame` 包含 api、ability_id、instance、occurrence、source、owner、params、step、data、event、target。初次 `answer` 为空；选择恢复时使用已验证的回答。返回 data 替换临时数据，因此需要继续使用的字段必须带到下一步。所有数据必须是普通可序列化值，不能包含对象、Callable、Signal 或循环引用。

引擎保存完整帧、未执行操作、操作游标和原堆叠对象。遇到防伤排序、自机返回等引擎选择时暂停后续操作；完成后从游标继续。玩家的步骤选择属于同一次结算，不创建响应窗口。状态检查、触发排队及展示确认继续由引擎决定。符卡全部完成后由引擎移动至墓地并应用已有替代。

临时帧永远不直接发送给客户端。操控者只收到当前选择规格及必要的隐藏牌查询副本；对手和观众收到等待状态及经过清理的公开结算来源。

## 模组状态与兼容性

`state` 必须在清单中声明，按包命名空间与操控者分开保存：

| scope | 生命周期 |
| --- | --- |
| match | 一局，开始新对局时清空 |
| turn | 当前回合，下一回合查询返回 null 且不再投影 |
| source | 来源 UID + epoch，移动区域后失效 |

visibility 为 public / owner / authority。authority 仅保存在权威存档；owner 仅向所属玩家投影；观众只收到 public。数据可见性由作者明确声明，不自动推断字典中的卡牌引用是否机密。

基础游戏指纹只含原卡库与规则清单；模组房间另存并精确比较已启用包的 ID、版本、接口版本和目录内容 SHA-256（忽略 .uid、.import 和隐藏目录）。多包清单按 ID 排序；多、少一个包都拒绝加入。存档恢复和观众入场使用相同检查。外部脚本从普通文件编译，不需要导入到 PCK；动态外部依赖不属于接口契约。

存档保存同一份清单。`StateCodec.restore` 返回空串表示恢复成功；版本／哈希／接口不匹配时返回错误并保持原引擎不变，调用方必须处理这个返回值。房主恢复已经接入此检查。回放保存包清单和经过投影的状态，不把脚本或私有结算帧写入回放。

## 常驻修正

静态脚本仅需 `validate(params)` 与 `get_modifiers(ctx, query, params)`。返回形如：

```gdscript
return [{"id":"anthem", "layer":30, "operation":"add", "value":2,
         "depends_on":["some.pack/ability/base"]}]
```

`id` 在该能力实例内稳定、唯一，不能随查询次数变化。依赖键为完整能力ID加 `/` 加修正ID；依赖同层所有匹配的能力实例。

| 层 | 顺序和用途 |
| --- | --- |
| 10 | 原基础属性之后、现有指示物和旧卡加减之前，设置基础值 |
| 30 | 现有指示物、旧卡加减、回合加减之后，模组加减或设置 |
| 40 | 最终乘算或覆盖；随后按现有规则限制攻击力／灵力最低为0 |

同层支持 `set`、`add`、`multiply`。先处理依赖，再按来源区域变化的引擎时间戳、稳定实例身份排序。每应用一次便重新收集未应用效果，重新计算数值和适用性；同一修正每次查询只应用一次。依赖循环按最早时间戳打破，再继续检查，不依赖加载顺序。跨层依赖不改变固定层顺序。查询最多应用128项修正；作者必须保持稳定ID和有界结果。

查询种类：`stat`（card/stat）、`keyword`（card/keyword）、`cost`（card/controller/color）、`cast_permission`（card/controller）、`target_protection`（target/controller/spell）、`action_lock`（card/controller/action，action为cast/activate/attack）。每次均含 `layer` 和当前 `value`；属性使用三层，颜色费用使用30/40层，布尔查询使用30层及布尔 `set`。费用非负，不影响已确定的不支付费用使用。布尔许可不能绕过其余时机、颜色约束、角色约束或费用验证。既有目标保护和行动禁止仍由引擎检查。

同一查询递归会回退到传入基值；同属性依赖应通过 `depends_on` 与 `query.value` 表达，不用递归查询自身最终值。查询上下文禁止操作；不能在脚本成员或全局变量累积查询结果。

## 替代效果

替代脚本仅需 `validate(params)` 与 `get_replacements(ctx, change, params)`；清单声明 `changes: ["draw"]` 或 `["cast_x"]`。这两种变化是v2支持范围，伤害、移动等变化不会发送此入口。

- `draw`：变化包含 owner、id、used、count；count 是本次仍欠抓的数量。返回 `{id, optional, cancel:true, operations:[...]}` 时仍按每张牌独立替代；每次完成后检查剩余抓牌。没有适用效果才执行抓牌或牌库不足判负。
- 道具批量替代抓牌可返回 `{id, optional:true, cancel:true, recover_draw:{pool:[卡牌引用], title:"选择道具"}}`。pool 必须是该玩家拥有、位于其移除区、UID及epoch有效且不重复的牌。数量不足以覆盖 count 时立即判负；足够时先确认是否发动，再使用统一选牌组件点选恰好 count 张移回手牌，同一牌不能重复选择。一个选牌步骤最多100张；更大的请求保留余数继续处理。作者应只从一个稳定来源返回同一组替代，避免重复提供相同卡池。
- `cast_x`：声明和费用完整验证、支付之后，使用事件之前。包含 owner、source、x、target；返回 `{id, optional, x:新值, operations:[]}`。改变结算及使用观察者看到的X，不追溯支付。

唯一且必选的替代自动应用；多个适用效果或选发效果由受影响玩家选择应用或跳过选发项。每次后重新检查来源区域版本与条件。同一变化保存已应用／已跳过的完整效果实例身份；取消原变化后不会再替代原抓牌。同一张牌再次抓取是新的变化。最多128次替代，不允许脚本改变used或直接提交变化。替代中的操作也保存游标，遇到自机返回等内在选择时暂停；v2不接受替代操作内部再次发出draw，避免生成递归抓牌变化。

队列保存变化、已用效果、剩余抓牌及原结算游标，可直接序列化；选择复用普通模式选择组件和权威 `choose_effect` 命令，不创建新响应窗口。客户端和观众不收到整个变化队列。

查询新增 `info(card_id)`、`units(owner=-1)`、`leaders(owner)`、`active_player()`、`turn()`、`x_casts(owner)`、`used_this_turn(key)`、`x_limit()`、`event()`。

命令新增 `life(owner,amount)`、`counters(ref,amount)`（三维正指示物）、`tap(ref,bool)`、`deck_move(ref,bottom=false)`、`enter(ref,timer=-1)`、`buff(ref,stats)`（本回合三项属性及疾行）、`random_damage(refs,amount)`。`move` 可带第三参数 tapped，用于横置进入颜色盘。随机选择由权威引擎RNG执行并保存，非目标随机伤害不会触发“成为目标”。新命令仍验证UID和区域版本，复用原区域移动、计时、生命、指示物及伤害规则。
