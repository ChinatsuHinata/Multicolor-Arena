# 双端 PCK 补丁

从本次 1.2.8.5 发布起，使用 `tools/publish-pck-update.ps1 -Publish -SkipBuild -FromVersion 1.2.8.4 -NoLegacyCumulative -ReplaceExisting` 只推送相邻差分。`-NoLegacyCumulative` 禁止创建或回退到新累计兼容包，只更新签名 `chain.json`，保留历史相邻路径与现有 `latest.json`。同版本重做使用 `-ReplaceExisting`，历史哈希文件保留；已经运行 1.2.8.5 的客户端仍不会按同版本号再次下载。完整包及新差分均包含两条依次推送的新公告，旧公告记录在新版初始化时撤下。

从 1.2.8.11 起，Windows 和 Android 设置页移除「加载 PCK 补丁…」按钮，更新继续由登录后的自动更新流程完成。补丁是单个 `.pck` 文件，内部包含 Godot PCK 和发行签名头。签名头写明游戏、平台、来源版本、目标版本、PCK 长度及 SHA-256。客户端先用 `data/update_public.pem` 验签，再逐字节核对 PCK，随后检查版本。

云端同时保留 **1.2.7.1 → 目标版本的累计补丁**和**上一版 → 目标版本的相邻补丁**。签名 `chain.json` 记录历史路径；客户端从已安装版本遍历完整路径，选择总下载字节数最少的一条。比如清单有 `1.2.7.1 → 1.2.7.2 → 1.2.7.3`，可以在一次登录检查中连续下载两份，再一次性提交安装记录，只提示重启一次；若直接累计补丁更小，则直接下载它。已在 1.2.7.2 的客户端只需后一份相邻补丁。

游戏将补丁保存在自身的 `user://patches/`，再次校验副本，然后写入加载顺序。自动更新会先下载并校验整条链，再保存所有副本，最后原子替换 `index.json`；下载、校验或提交失败时保留原来的安装记录，并清理本次临时文件。安装后的待生效版本也会参与检查，避免重启前重复下载。Windows 安装版重启后生效；Android 退出并重新打开后生效。启动时补丁管理器在主场景加载前按顺序再次验签、核对哈希和版本，再挂载 PCK。若任一项失败，后续补丁不会挂载，游戏会提示错误。版本号会更新到当前运行的项目设置，供界面、联机和回放使用。

## 制作

先在 **1.2.7.1 源码状态**运行 `tools/build-pck-base.ps1`，保存 Windows 和 Android 两份基底 PCK，并确保发行给玩家的 1.2.7.1 包使用对应的相同资源。客户端的自动检查代码也必须包含在这个基底版本中；已发行且没有自动更新代码的旧包无法自己获得此功能。

随后把 `project.godot` 的 `config/version` 改成目标版本，使用与发行更新清单相同的本地私钥 `.godot-toolchain/release-signing.key`。在项目根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build-pck-patch.ps1
```

脚本使用 Godot `--export-patch` 和对应平台的来源版本完整 PCK 导出**实际差分资源包**，再签名并封装到 `builds/pck-patches/<来源>-to-<目标>/`。默认来源仍是 1.2.7.1；可传 `-FromVersion 1.2.7.2` 制作相邻补丁。来源完整 PCK 默认读取 `builds/pck-base/<来源>-windows.pck` 和 `<来源>-android.pck`，也可通过 `-BaseWindowsPck`、`-BaseAndroidPck` 指定。差分 PCK 不能当作下一版的完整来源包。

正常构建还会导出并核对 `builds/pck-base/<目标>-<平台>.pck` 完整快照，供下一版增量导出。两个平台的文件不能互换。已有 `raw-windows.pck` 和 `raw-android.pck` 时可加 `-SkipExport` 重新签名封装；该选项不重新导出完整快照。补丁可覆盖脚本和资源，但不会更换 Godot 引擎、Windows EXE 或 Android 原生代码。需要更换引擎或原生部分时应发布完整安装包。

## 登录时自动更新

发现需要下载的补丁后会弹出下载窗口，按整条补丁链的已下载字节显示进度。点击“隐藏，继续下载”后下载仍在后台进行，可用右上角“查看更新进度”再次打开。检查、下载和安装期间不能进入云端房间；补丁安装成功后需重启游戏才能进入云端对局。下载失败时解除进入限制，保留原安装记录。

账号登录或自动登录成功后，客户端读取 `http://8.137.122.187:47862/updates/pck/chain.json`。仅当此入口返回 404 时，回退到原 `latest.json` 单包方案。清单和 PCK 均使用发行密钥签名；客户端还会核对平台、来源/目标版本、下载地址、大小和 SHA-256。没有完整路径、存在重复路径、校验失败时停止更新并保留旧安装。云端不可用时不会阻止登录。

`tools/publish-pck-update.ps1 -Publish` 在构建前检查云端清单并用本地公钥验签。默认以上一已发布版本为来源，生成相邻补丁，再生成 1.2.7.1 累计补丁；上传前逐份核对 PCK 签名、平台、来源及目标。云端历史路径合并进新的签名 `chain.json`，原 `latest.json` 始终只含累计补丁，供旧客户端使用。累计补丁和相邻补丁的下载地址不同，不会混用。

若上一版是旧流程发布、没有保存来源完整快照，自动流程会明确提示并回退到 1.2.7.1 累计补丁，保存当前完整快照，后续发布即可自动使用上一版。也可显式传 `-FromVersion 1.2.7.1`。已有双端成品时加 `-SkipBuild`；缺少自动选定的相邻补丁时会提示并仅发布累计补丁。显式传入来源版本或自定义来源 PCK 时严格要求对应文件存在，不自动回退。

只准备本地清单可省略 `-Publish`；默认从 1.2.7.1 制作。若要在本地合并历史链，传 `-PreviousManifest <已有签名清单>`，清单同样必须通过公钥验签。实际推送始终读取云端当前清单。

上传先在独立暂存目录核对所有哈希，再取得发布锁，核对云端清单仍与构建前一致，保存文件并切换两份清单。另一发布者已改变清单时拒绝提交，重新运行即可重新合并。`chain.json` 使用包含整个文件 SHA-256 的不可变地址；旧哈希文件会保留，避免同版本覆盖打断已开始的下载。原累计补丁地址不长期缓存。

2026-10-02 已单独部署更新后的 `relay/update_gateway.py`，公网 ECS 现已支持 `/updates/pck/chain.json`、任意来源版本及带哈希的 PCK 地址。正式版本仍为 1.2.7.2；新增发行签名的 `chain.json` 记录已有的 1.2.7.1 → 1.2.7.2 真实补丁，并提供相同补丁字节的哈希地址，原 `latest.json` 与旧下载地址保持不变。公网双平台完整下载、签名、SHA-256、HTTP Range、HEAD 和 WebSocket 转发均已通过验证；此次只重启下载网关，账号及游戏中转进程保持运行，并保存旧网关回滚备份。后续发布继续使用 `tools/publish-pck-update.ps1 -Publish` 合并真实版本链。

目标仍读取 `project.godot`。已导出原始 PCK 时可选择 **PCK: 仅重新签名封装双端补丁**，同样自动识别安装版实际版本。云端构建、推送任务也使用安装版基线，并保留 1.2.7.1 累计兼容包。安装路径不同可向脚本传 `-WindowsInstallDir`，补丁用户目录不同可传 `-InstalledPatchDir`。直接运行构建脚本且未传 `-UseInstalledWindowsPck` 或 `-FromVersion` 时仍默认使用 1.2.7.1。任务定义在 `.vscode/tasks.json`。

## 虚拟版本自动更新测试

选择 **PCK: 用虚拟新版本测试安装版自动更新**，或运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\test-installed-pck-update.ps1
```

脚本取高于源码和已安装版的虚拟版本，可通过 `-TestVersion` 指定。它复制发行 EXE，并为当前源码建立独立导出项目，制作实际的资源差分。测试私钥独立生成，PCK 签名头含 `test_only`，资源含 `data/pck_virtual_version.json` 的 `TEST_ONLY` 标记。已有发行补丁先由发行公钥验证，再在测试副本中保留相同资源字节、换用测试签名，从而复现原安装版的完整补丁链。

回环 HTTP 服务只监听 `127.0.0.1`。发行 EXE 副本使用隔离用户目录，调用实际游戏的成功登录回调触发自动下载，验证追加安装记录；第二次启动验证新版本生效、资源逐文件与完整目标快照一致，并确认不会再次下载同一补丁。测试完成后停止本地服务，结果及日志保存在 `builds/pck-tests/TEST_ONLY-<版本>-<随机编号>/result.json`。测试不会修改源码版本、真实安装目录、玩家补丁目录或正式云端清单。测试 PCK 仅供隔离测试，不能发给玩家；正常发布流程无法通过其发行公钥验签。

## 云端推送连接排查

推送脚本在构建前检查 SSH 和暂存目录，失败时保留 SSH/SCP 原始输出与退出码。可单独运行 VS Code 任务 **PCK: 检查云端推送连接**，或 `tools/publish-pck-update.ps1 -CheckConnection`；它只检查 SSH 连接和认证，不构建、签名或上传文件。

`kex_exchange_identification: read: Connection reset` 表示 SSH 握手阶段连接被重置，创建目录的命令尚未执行。先检查本机代理/TUN/VPN 路径，可将 `8.137.122.187` 设置为直连后复测；若直连仍失败，检查 ECS 的 SSH 服务日志和来源 IP 限制。无需修改补丁版本或重新构建即可重试连接；连接恢复后使用 **PCK: 推送已构建差分更新包到云端** 继续上传。
