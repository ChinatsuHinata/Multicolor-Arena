# Windows 修复补丁安装包

`tools/build-patch.ps1` 根据旧版和新版 Windows 导出的 `MulticolorArena.exe`、`MulticolorArena.pck` 制作差分安装包。玩家先安装指定旧版，再运行补丁安装器。补丁会检查已安装版本及两个程序文件的 SHA-256，校验失败就停止，不会修改玩家的 `deck`、`replay` 或 Godot 用户数据。

## 制作

1. 在 `project.godot` 中把 `config/version` 改为新版本，保留旧版正式发布时的 EXE/PCK，放在 `builds/installer-staging/<旧版本>/`，或用 `-BaseDir` 指定它们所在的目录。旧文件必须与玩家安装的文件逐字节相同。
2. 在项目根目录运行：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build-patch.ps1 -FromVersion '1.2.1'
   ```

   脚本会使用 `tools/build-windows.ps1` 导出新版本，再生成和验证差分。需要 Godot 4.7.2 导出环境及 Inno Setup 6/7；如果编译器没有自动找到，传入 `-IsccPath 'C:\...\ISCC.exe'`。
3. 已经导出新版时，可使用 `-SkipExport`。新版必须位于 `builds/installer-staging/<新版本>/`，且确实对应准备发布的源码：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build-patch.ps1 -FromVersion '1.2.1' -SkipExport
   ```

产物是 `builds/installers/MulticolorArena-<旧版本>-to-<新版本>-win64-patch.exe`。差分数据和临时脚本保存在 `builds/patch-staging/`。构建时脚本会先在临时副本上应用补丁，并用 SHA-256 核对还原后的 EXE/PCK，然后才编译安装器。

## 玩家安装

关闭游戏后运行补丁安装器。它只接受对应旧版的 Inno Setup 安装记录和原版 EXE/PCK；便携 ZIP 版、其他版本或内容被改动的文件无法直接使用此安装器。应用时先在安装目录生成并校验新版文件，再替换旧文件。该过程需要足够的可用磁盘空间容纳临时 PCK 文件。完成后沿用原安装记录与卸载程序。

差分包只适用于指定的旧版到新版组合。发布给其他旧版时，分别以该版正式导出文件作为 `-BaseDir` 再制作一份补丁。若新旧资源差异很大，差分包也可能较大；这时可继续提供完整安装包。
