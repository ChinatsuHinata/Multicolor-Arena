# 卡牌数据库与编写说明

版本：v0.10，2026-09-19。

## 数据如何进入游戏

`cards/卡牌ID.json → card_database.gd 校验并转换 → 组卡器与 duel_engine.gd 共用定义 → demo_abilities.gd / expanded_abilities.gd 执行登记的能力`

卡图统一存放在 `recourse/数据库/卡牌ID.扩展名`，JSON的“图片”必须指向这里。`recourse/新增卡片`仅为等待处理的原始卡图目录，不自动加载到卡池；新增文件不会因为启动游戏或更新索引就自动导入。正式导入顺序是先将指定图片移动到数据库目录，再编写卡牌资料和规则，最后登记可用ID。

旧存档的 68、70 等 ID 保持不变。一个 ID 表示一种规则卡，每局中的不同张牌另有实例 ID；换区增加区域版本，防止离场又回来的牌继续被旧目标引用。新卡建议使用含系列与类别的稳定 ID，避免未来编号重复。

## 人工修改一张卡

1. 获得本批卡牌的导入指令后，先确定稳定ID，把指定图片从 `recourse/新增卡片` 移动至 `recourse/数据库/ID.png` 或 `ID.jpg`，保留原图片内容并同步Godot导入配置。再复制对应JSON，填写ID、完整名称、类别、颜色、费用、图片和能力文字。“图片”示例：`res://recourse/数据库/177.png`。
2. 单位填写角色名、称号、种族、攻击力、血量和灵力；角色符卡填写角色约束，高速牌填写 `"高速": true`。
3. 使用 `能力绑定` 引用下表已登记的实现，填写参数。**能力文字只负责显示，不会被自动解释执行。**
4. 在 `card_database.gd` 的 `IDS` 中登记新 ID。先通过规则测试，再加入可用卡池；未知能力会被拒绝。
5. 若需要新增机制，先写 GDScript 能力并加入 `HANDLERS`，接到对应触发、结算或查询入口。新增的能力参数也要在 `validate_definition` 中校验。
6. 完成已登记数据后，用Python执行 `tools/check_card_database.py --write-index` 更新已有卡图清单，再执行 `tools/check_card_database.py` 核对路径和SHA256。这两个命令都不会扫描待导入目录或新增卡牌ID。单纯修改已入库卡牌的文字或数值不需要重新移动图片。

已有伤害效果的参数写法：

```json
"能力绑定": [
  { "实现": "damage", "参数": { "数值": 5 } }
]
```

产色效果写法：

```json
"能力绑定": [
  { "实现": "mana", "参数": { "颜色": "黄" } }
]
```

修改效果数值时，同步修改 `能力文字` 和 `完整说明`。`完整说明`保留牌表资料；组卡器和战场预览只显示`能力文字`，不会重新堆出费用、攻击力、编号等说明。玩家可见文字保留原牌文和关键词，不添加关键词定义；没有能力时可填空字符串，字段仍必须存在且为字符串。规则解释与来源可留在`完整说明`或开发文档中。

| 实现 ID | 参数 | 生效入口 |
| --- | --- | --- |
| damage | 数值：非负整数 | 符卡结算，复查目标后伤害 |
| counter_card | 无 | 符卡结算，将目标实体牌移出堆叠 |
| mana | 颜色：五色之一 | 支付查询，确认提交时横置道具 |
| marisa_enter | 数值：非负整数 | 实际进场后收集可选单位伤害触发 |
| marisa_spell | 数值：非负整数 | 操控者使用符卡且来源具自机能力时收集触发 |
| brave | 无 | 已攻击单位在己方结束阶段开始时将重置能力入堆叠 |
| exterminate | 无 | 获得自机能力时改变合法阻挡者查询 |
| grant_leader_abilities | 无 | 当前战场上的持续能力查询 |
| annihilate | 无 | 己方主要阶段战斗伤判中，进攻单位杀死至少一个阻挡者时对对手造成自身灵力伤害；多杀只计一次 |
| flash | 无 | 单位的使用时机扩展至合法响应窗口；不会突破调度、凭依、结算等不可行动状态 |
| turn_buff | 攻击力、血量、灵力：非负整数；疾行：布尔值 | 目标单位结算后获得可叠加的本回合修正；回合结束或换区清除 |
| activated_damage | 数值、费用、横置；绑定可附名称 | 点击永久物选择启动异能，私有选目标/支付，确认后能力入堆叠 |

这些名字是实现绑定，不是自由中文程序；不能只写一个未实现的关键词就得到效果。当前登记的61张卡有明确能力实现，包括本批计时符卡；通用复制、梦违或开局增牌仍须扩展引擎。

## 构筑资格与运行时实例

`构筑资格.允许常规构筑`决定能否放入保存卡组；测试开关也不跳过这一禁入条件。创建对局实例与这个字段分离，因此以后允许由已实现的能力引入禁入常规构筑的卡。

当前没有导入梦违，也没有宣称已实现从局外取得牌或开局加入牌库。后续应加入单独的运行时卡池登记、开局事件、来源记录和选择范围；不要把梦违伪装成副卡或衍生物。

## 支付与动作边界

所有手动选择暂存在 `duel_view.local`。预付时不移动手牌、不横置引擎中的资源、不消耗红薯，也不修改对局记录。最后一次 `commit_cast` 或 `commit_ability` 重新检查时机、约束、目标和整套费用，全部合法后一次提交。取消只删除本地预选。

自动支付枚举合法的精确付款，比较固定代价：产色道具8、单色盘10、双色盘20、红薯1000，选总代价最低方案。这里的“最优”指这一公开、可修改的资源保留策略，不是预测后续所有回合的最优胜率。玩家先确认声明，再计算付款；只有一种合法分配时免去额外的支付方式询问。

## 最低验证要求

新卡至少检查正常使用、使用约束、取消或非法付款不改变状态、目标离场、响应或反制，以及主要能力和自机能力的区别。涉及构筑/开局/替代效应的卡还需要对应的专门测试。

当前测试入口位于 `tests/`，结果与画面检查位于 `work/`；测试用卡组文件独立于 `saves/decks.json`。


## v0.6：行动菜单与启动伤害异能

行动菜单使用 `available_actions` 查询攻击与已实现的启动能力。只有攻击一种可用行动时预选金边和剑，点击右下角攻击按钮才宣攻；存在多种可用行动时，名称显示在右侧的单独卡面下，不显示禁用项及召唤失调解释。蓝边和响应判断使用同一套合法性查询，黄边表示选中。不要把进场触发、自机触发、英勇和持续能力改成随时点击使用。

以下是可供新卡作者使用的能力绑定示例，不是现有魔理沙或灵梦的牌文修改：

```json
"能力绑定": [
  {
    "实现": "activated_damage",
    "名称": "横置：造成 1 点伤害",
    "参数": { "数值": 1, "费用": {}, "横置": true }
  }
]
```

该实现可绑定永久物，目标为单位或玩家；可以同时设置颜色费用。至少需要横置或正数颜色费用。单位用横置支付时受召唤失调限制，不能重复横置同一来源来同时支付产色和启动费用。确认前所有费用保存在本地；确认后来源留在战场，能力对象单独进入堆叠。

当前八张的正式定义未增加这种启动伤害。多行动界面由测试时临时注入的能力验证，测试后重新加载正式卡池。此扩展目前覆盖玩家的启动伤害交互；加入正式新卡时，还需补人机选择该异能的策略及针对卡文的测试。


## v0.7：普通单位与临时强化

该批已入库卡牌的原图现位于`recourse/数据库/`，按稳定ID命名。单位来源为全牌表`CHARACTER (单位)`第53、56、57、59、60行；符卡来源为`SPELL （符卡）`第4、20行。关键词解释核对牌表`CAPACITY(能力词条)`图示。每张JSON记录自己的来源定位。

普通单位使用`"类别": "单位"`，没有角色名和称号时填空字符串，不能用`/`作为所有普通单位的共同称号。普通单位不受自机颜色约束，允许同名的多个实例在战场共存，但构筑仍受同名数量限制；不能放入自机位。

本回合强化示例：

```json
"能力绑定": [
  { "实现": "turn_buff", "参数": { "攻击力": 2, "血量": 0, "灵力": 1, "疾行": true } }
]
```

`duel_engine.stat`统一计算即时攻击力、血量和灵力，伤害分配、伤判、胜负检查、人机和显示读取即时值。修正附在对局实例上，不改共享卡牌定义；多个修正相加，目标换区后旧目标失效，回合结束时清除。

疾行按词条允许进场回合攻击，不把横置启动异能的召唤失调限制一并删除。龙宫使者的“任意时机使用”允许合法响应窗口入堆叠，与疾行分开。人机已接入新增高速伤害、强化与响应使用单位的选择；每次新增不同机制仍需专门策略和测试。

旧「载入测试卡组」保持原八张演示组合；新增七张可自行在编辑器组入卡组，不会自动修改玩家存档。


## v0.8：展示与规则分离

召唤失调仍由引擎执行，只移除界面文字标记。面板攻防灵力逐项比较印刷数值，血量展示当前血量上限减已受伤害；高于原值绿色，低于原值红色。横置变暗只修改该实例的展示材质，不影响同名卡或基础卡图。

战斗伤判先由规则层原子结算；展示层保留伤判前的网格，播放剑/盾标记及逐个碰撞，完成后同步死亡离场及结果界面。动画期间暂停后续人机行动，不由动画回调造成第二次伤害。

「观察战场」是界面状态：隐藏选择面板，保留同一面板实例、私有目标和付款、伤害分配数值，暂停对局推进。返回时继续原选择；观察中仅允许查看与缩放，不允许通过牌面提交新行动。


## v0.8.1：无合法阻挡者与堆叠边框

在攻击响应窗口结束、即将选择阻挡者时，查询实际的`legal_blockers`。结果为空则通过原有`block([])`提交不阻挡，不创建玩家选择；结果非空保留手动选择。该查询包含横置及退治等限制，并允许攻击响应期间进场的新单位成为阻挡者。只省略无意义选择，不跳过合法符卡/异能响应窗口。

堆叠布局固定关闭选择边框与光晕，适用于双方实体牌及能力副本；来源永久物和手牌的蓝黄选择样式独立保留。


## v0.8.2：三档响应

`duel_view.ResponseMode`为`DEFAULT / ON / OFF`三档，默认`DEFAULT`。`in_response_window`限定为己方持有执行权、没有必须处理的选择、不是调度也不是己方自由主要阶段；`should_ask_response`统一决定提示和自动让过：开始终询问，默认读取`engine.has_response(0)`，关始终让过。

默认档的合法响应包括满足费用和目标条件的高速符卡、可响应使用的单位，以及可用启动异能。关档同时取消该窗口内的手牌/异能操作入口和候选蓝边，避免自动让过前的短暂可点击机会。切到关时，尚未提交的响应目标和付款在本地清空，不横置资源、不改变手牌和公开日志。强制触发目标、阻挡、凭依、调度、弃牌等规则选择继续保留。


## v0.9：扩展能力与调试

数据库增加 `关键词`、`符卡类型`、`计时`。费用可以为 0；零费用卡仍需满足角色约束和目标条件。扩展绑定格式：

```json
"能力绑定": [
  {"实现": "extension", "参数": {"效果": "enter_haste"}}
]
```

`card_database.EXTENSION_EFFECTS`校验已登记效果。添加新效果必须同时实现事件入口、合法选择、结算和测试；仅在 JSON 填英文名称不构成实现。完整映射见新增清单。常用入口如下：

| 入口 | 责任 |
| --- | --- |
| `spell_options / spell_resolve` | 使用时的模式、目标、额外牺牲声明及符卡结算 |
| `on_enter / on_leave / on_death` | 进场、离场、死亡事件，使用最后已知信息 |
| `trigger_options / resolve_trigger` | 触发选择与堆叠结算；目标包括墓地、颜色盘、复合目标 |
| `activation_options / activation_cost / resolve_activation` | 墓地启动、横置移除、牺牲强化、每回合限次返回 |
| `duel_engine.move_to / detach / enter_field` | 实例换区、区域版本、进场合法性、自机返回和衍生物消失 |
| `delayed / run_delayed` | 指定下一准备／结束阶段的返回或牺牲，校验原实例区域版本 |
| `add_timer / choose_timer` | 本批咲夜的计时增加／减少替代选择 |
| `deals_combat_damage` | 先制与后续伤判响应窗口 |

`plus_counters`为持久数值指示物，换区清除；`modifiers`为本回合修正，可正可负。`poverty`限制凭依。时符留在战场但不是永久物，出鞘只移除永久物。反魂蝶计时清算只进行一次，归零按卡文失败；投降仍可结束。

飞碟和半灵在规则引擎初始化时登记局内定义，不暴露在常规组卡器。衍生物使用独立空白示意图，不借用其他卡的规则。普通人机的隐藏信息保持；只有当前本地会话的关于页暗号开启后，界面跟随执行权控制双方。所有调试移动都有引擎校验，不能靠界面绕过构筑存档保护。

当前策略是启发式人机；能使用本批新卡与合法高速响应、墓地启动，并不保证选择最强线路。v0.9.4已加入当前事件队列的同时触发排序；完整替代效应组合框架、复制与联网确定性回放仍在后续计划。


## v0.9.3：目标预选与触发次数

`target_picker.gd` 将引擎给出的合法候选分为模式、牺牲费用、目标、颜色和复合目标步骤；只保存私有选择，确认时提交完整的原始候选。对象目标由蓝边提示、金边选中，玩家生命按钮也是可选对象。无需目标的卡也必须先确认声明，再自动或手动支付，最终提交前右键可以取消。`stack_arrows.gd` 跟踪已提交的目标引用与区域版本，纯展示，不改变规则状态。

幽幽子的 `leader_death_damage` 绑定包含「伤害」=1、「每回合次数」=2；触发时捕获这两个数值。同一次死亡按来源实例/版本和死亡实例/版本去重，次数在玩家确认能力进入堆叠时累计，拒绝使用不累计；下一回合重置。每次触发拥有独立的UI预选，不能继承上一次的选中目标。

## v0.9.4：必发入堆叠、触发排序与单条能力说明

`Extra.event` 的 `optional=false` 表示必发。到合法处理时点，`begin_trigger` 先插入堆叠；需要目标则记录 `awaiting_target` 与 `pending.stack_id`。目标确认通过 `complete_trigger_target` 更新原对象，不再插入一次。选发仍确认后入堆叠，拒绝不计次数。

`trigger_order` 的候选仅含同一操控者待入堆叠的触发；主回合玩家先选择。通用启动异能不出现在这个菜单。英勇结束阶段触发也走该队列。人机可处理新的排序状态，调试接管时由玩家点选。

`ability_caption.gd` 按实际执行的效果键显示一条小字，动态伤害使用能力数据；通用启动伤害能力使用该绑定的“名称”。新增特殊实现时同步增加对应说明，不应把整张牌的多个能力拼成堆叠说明。关键词能力只显示关键词。

规则依据及交互细节见 [触发能力时机与排序](C:/Users/tzx20/Documents/test/docs/触发能力时机与排序.md)。

## v0.9.6：混色费用、伤判快照与区域标签

卡牌的中文费用字段支持用斜线分隔一组可替换的颜色。例如：

```json
"颜色": ["红", "蓝", "绿", "黑"],
"费用": {"红/蓝/绿": 3, "黑": 1}
```

三点共用一个计数池，可由红红红、蓝蓝蓝、红蓝绿等任意组合支付；一点黑是额外要求。每个实体资源仍只能使用一次。牌色与费用分开：此卡在颜色盘中能选红蓝绿黑之一，不能凭一张四色卡提供四点。现有单色费用格式继续兼容；本轮混色格式用于卡牌费用，启动绑定字段仍按原有校验约定。

`color_cost.gd`负责对已选颜色进行可行分配，供`payment_valid`与手动支付候选共享；`payment_search`按相同颜色组选自动方案，并沿用优先道具、低灵活度资源、保留红薯的评分。预留不横置实体，最终确认才提交，右键取消不改变公开状态。

`combat_damage`只接受`block_window`中的一次提交。每次伤判生成递增`damage_batch`和包含计算后攻守灵力的`damage_snapshot`，再执行引擎判定。显示层按批次播放碰撞，在`combat_damage_shown`时刷新快照数值，保留`damage_hold_seconds=1.0`秒后同步离场。动画期间不推进人机或接受新行动；先制与普通伤判有不同批次，伤害窗口的重复提交无效。负血量不截断，避免死亡时先清除damage导致显示恢复。

`available_hand_zones`只为当前有合法动作的墓地、除外或牌库创建标签；`region_action_cards`使用现有`cast_error`与`extension_activation_error`，不额外放宽执行权、角色约束、付款或目标条件。普通牌库浏览仍隐藏卡面；仅允许从牌库使用的合法牌出现在牌库操作标签中。`open_deck_casts`兼容入口也转到标签，不创建没有取消出口的模态窗口。

普通牌堆侧栏由场上的牌堆点击打开，3列卡面；`history_open`、观察、目标/付款、调试拖动和模态选择暂停流程，单纯`debug_open`牌堆浏览不再暂停。调试直接拖动使用物理实例UID，堆叠能力副本不可当成新卡；移入牌库使用`push_front`。除外槽由`MAT_SLOTS.exile`定位，空牌堆隐藏并关闭碰撞。

50张图片的原路径已迁移到`recourse/demo素材`，相应JSON已更新；完整映射在`work/v096-relocated-art.json`。素材没有重命名或重复生成。

## v0.10：预组效果与人工编写入口

完整新卡清单及预组配比见 `新增卡片与预组-v0.10.md`。本批绑定形式：

```json
{"实现":"precon","名称":"这里填写卡面能力原文","参数":{"效果":"ramp_enter"}}
```

`card_database.gd` 的 `PRECON_EFFECTS` 明确允许的效果键；`precon_abilities.gd` 负责进离场、启动、触发、支付修正、动态关键词和结算。不要仅添加允许键而不实现实际逻辑。

- `衍生物:true` 搭配 `构筑资格.允许常规构筑:false`，允许无色衍生物资料，但禁止玩家放入套牌。
- `可变费用:"黄"` 记录X所在颜色；使用声明保存X，支付用实际X，堆叠费用值包含X，离开堆叠后按普通区域规则处理。
- `别名:["恋符「极限火花」"]` 只供明确涉及牌名的效果匹配；构筑同名计数仍按完整印刷卡名。
- 多目标使用 `{selection:[{pool,min,max,title,distinct_names,exclude_previous}],selection_id}` 描述约束，不生成所有排列。提交为 `{selection_id,picks:[[引用],...]}`，规则层再次验证数量、顺序、唯一性和区域版本。
- 结算中的检索、交换调用 `continue_choice`。它挂起当前效果并等待卡面选择，`choose_effect` 恢复同一次结算；不要将每一小步作为新触发重复入堆叠。
- 实例 `original_owner` 与 `owner` 分别表示拥有者和当前操控者。借用对手除外牌时维持前者，去墓地或手牌等区域恢复拥有者，换区版本阻止旧目标追踪。
- 横置通过 `tap_card`、回复生命通过 `gain_life`、伤害通过 `damage_target` 派发事件，避免直接改字段漏触发。`damage_context` 区分战斗、来源及单一伤害目标；选取费用或回收牌不算额外伤害目标。
- 独立防避次数保存在实例 `wards`；回合结束清理临时效果。时符0计时和幻象条件在状态检查处理，时符与乐章留场但不是永久物。

新增效果应测试合法性、付款取消、目标失效、结算连续选择、原拥有者换区与至少一场完整对局。资料导入与实现不可只停留在预览文字。


## v0.11：Excel原文、倍率与新效果模块

卡图文本与Excel不一致时，以Excel为准。新增 `Excel来源` 保存文件、工作表、行、编号；已入库原图不修改，不把识别文字当执行代码。

绑定示例：`{"实现":"roster","名称":"该牌对每个单位造成3点伤害。","参数":{"效果":"sweep_three"}}`。对应允许键在 `card_database.gd/ROSTER_EFFECTS`，实现入口在 `rules/excel_abilities.gd`。必须同时具备实现、合法目标和专项测试，不能只增加注册键。

`可变费用`记录X的颜色，`X费用倍率`为正整数（默认1，2X填写2）。支付与堆叠费用值都乘倍率，效应中的X仍是玩家选择值。免费替代使用时X为0。

生命周期区分提交费用、触发入堆叠、结算中的连续选择、状态检查和清理；费用选择仍在提交前私有。每个启动异能传入自己的效果键，不能总执行卡牌的第一个启动能力。检索/弃牌/排列用现有分组描述；分配伤害允许不同分组重复同一个对象，结算时汇总后一次造成伤害。

增加指示物调用 `Roster.plus`，掷硬币调用 `engine.flip_coin`，付款通过既有payment接口，伤害通过damage_target。动态属性由stat_adjust计算，禁止把临时光环直接永久写入基本属性。复制实例的定义在当前引擎内，不能污染组卡用的全局卡库。


## v0.12：面具、指示物与多模式
