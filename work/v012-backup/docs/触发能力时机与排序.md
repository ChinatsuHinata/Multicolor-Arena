# 触发能力时机与排序

核对日期：2026-09-18。来源：[《极彩multicolour》完整规则2026.6(beta).docx](C:/Users/tzx20/Documents/test/recourse/《极彩multicolour》完整规则2026.6(beta).docx)，项目中的全文提取位于 `work/rules_review/complete_rules.txt`。

## 规则与结论

- **1.142a**：“若满足触发条件的多个能力即将触发，则它们将由其操控的玩家自行决定先后顺序，之后将它们放进对抗中。”其附注说明：触发时不会立即进入对抗，等待牌手获得动作执行权时一起进入对抗。
- **1.141b**：玩家具有动作执行权时可以起动启动类能力。
- **1.143a**：阶段开始的规则动作解决、触发能力进入对抗之后，主回合玩家得到动作执行权。
- **1.142d**：牌或能力结算中的选择和动作不会给玩家动作执行权。
- **1.12、1.13**：多位玩家同时选择时主回合玩家先选择；同一玩家多个选择没有指定顺序时，可自行选择顺序。
- **1.144、1.145a**：双方让过后结算顶端；获得动作执行权后可以用合法牌或能力响应已有对抗。

据此，本项目采用的解释是：**同一操控者可排序同时待处理的触发能力，包括必发与选发；不能为抢在待入堆叠的触发能力之前，插入启动异能。** 待处理触发完成后，仍可在获得动作执行权时启动异能，后入堆叠者先结算。没有把“可以”理解为可以把该次触发留到任意后续时刻。

规则没有另设一条允许“选发触发与启动异能自由混排”的例外。以上时机结论来自这些条文的合并解释，不是额外援引万智牌规则。选发与必发仍以当前卡牌中“可以”等措辞及明确绑定为依据。

## v0.9.4 交互与状态

1. 当前动作或结算完成，处理规则选择，再收集待入堆叠的触发能力。多个同操控者触发通过右侧多张卡面选择入堆叠顺序；卡面下仅显示对应的一条能力。双方都有选择时主回合玩家先选择。
2. 单个必发触发，或排到的必发触发，立即显示堆叠卡面。有目标时标记为待选目标；合法目标蓝边，点击金边，右下角确定。无目标触发直接成为完整堆叠对象。
3. 待选目标期间不发放响应或结算机会。右键只能清掉预选，不能跳过必发。确认是在同一堆叠对象上补全目标，不产生第二份能力。随后出现目标箭头。
4. 选发触发在右下角显示“是否发动xxx的触发效果”。有目标时选目标并确定才入堆叠；无目标时直接确定。点“不使用”跳过，不增加使用次数。
5. 所有待处理选择完成，才恢复合法响应；保留“开／默认／关”三档。多个能力仍最后进入堆叠的先结算。

“必发立即显示”是本次要求的界面流程：在合法的入堆叠处理时点先展示、再完成目标声明，不是在另一张牌结算到一半时插入响应。没有合法目标的触发继续按现有引擎跳过，避免产生无法完成的选择。

## v0.9.8：妖梦、死亡触发与两次伤判

按用户本轮确认，以及完整规则5.5.4、6.4.2a与1.22.4，伤害不是将妖梦的除外直接替换为死亡处理：

1. 先制单位造成本次战斗伤害，随后检查致死伤害。死亡单位送墓，收集死亡触发与战斗伤害触发。
2. 触发按既有排序入堆叠。妖梦的除外结算只移除仍在场的原单位，不能跟随它进入墓地；死亡后重新进场也属于新的实例，不会被旧能力追踪。
3. 无响应时，存活受伤者由除外能力移走，因此不参加普通伤判。该过程保留正常堆叠与响应，并非无堆叠的替代效应。
4. 若除外未生效，例如被反制，仍在场的非先制单位继续造成普通伤害。先制单位不会在普通伤判中重复造成伤害。双方均先制时，先同时造成伤害，之后的除外不能撤销已造成的伤害。

举例：自机妖梦2点先制伤害打死2血的水桥帕露西，帕露西进入墓地，其死亡能力照常触发；对5血单位造成2点伤害后，该单位存活，妖梦异能结算将其除外，不再反击。仅为普通副本且没有自机能力的妖梦，则不会触发除外。

本轮验证现有引擎已符合上述顺序，补充时机注释与专门回归用例，没有将死亡改成直接除外。测试入口为 `tests/test_v098_rules.gd` 与 `tests/test_v098.gd`。
